## 系统概述

### 功能特性

- **实时监控**: 持续监控系统资源和应用健康状态
- **多层告警**: 支持邮件、Slack、企业微信等多种通知方式
- **告警聚合**: 防止告警风暴，相同告警5分钟内只发送一次
- **性能分析**: 收集历史指标，支持性能趋势分析
- **自动恢复**: 检测到故障时自动触发恢复流程

## 安装和配置

### 前置条件

- Node.js 18+
- PM2 (已安装)
- 邮件服务 (可选)
- Slack工作区 (可选)
- 企业微信 (可选)

### 安装依赖

```bash
cd /path/to/grt-implementation-plan

# 安装监控服务依赖
npm install axios nodemailer

# 编译TypeScript
npm run build
```

### 环境变量配置

创建或编辑`.env`文件：

```bash
# 监控配置
CPU_THRESHOLD=80              # CPU使用率告警阈值 (%)
MEMORY_THRESHOLD=85           # 内存使用率告警阈值 (%)
DISK_THRESHOLD=90             # 磁盘使用率告警阈值 (%)
MONITOR_INTERVAL=60000        # 监控间隔 (毫秒)
HEALTH_CHECK_URL=http://localhost:3000/api/health

# 告警通知
ALERT_EMAIL=admin@company.com

# Slack (可选)
SLACK_WEBHOOK=https://hooks.slack.com/services/YOUR/WEBHOOK/URL

# 企业微信 (可选)
WECHAT_WEBHOOK=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=YOUR_KEY

# 数据库
DATABASE_URL=mysql://root:password@localhost:3306/grt
```

### 启动监控服务

```bash
# 使用PM2启动
pm2 start ecosystem.config.js --only grt-monitor

# 查看监控服务状态
pm2 status

# 查看监控服务日志
pm2 logs grt-monitor
```

## 监控指标

### CPU监控

**指标**:
- CPU使用率 (%)
- CPU核心数
- 系统负载平均值 (1分钟, 5分钟, 15分钟)

**告警条件**:
- CPU使用率 > 80% 时发送警告告警
- CPU使用率 > 95% 时发送严重告警

**示例**:

```
CPU使用率: 85.5%
CPU核心数: 8
系统负载: [2.5, 2.3, 2.1]
```

### 内存监控

**指标**:
- 内存使用量 (字节)
- 总内存 (字节)
- 可用内存 (字节)
- 内存使用率 (%)

**告警条件**:
- 内存使用率 > 85% 时发送警告告警
- 内存使用率 > 95% 时发送严重告警

**示例**:

```
内存使用率: 87.3%
已用内存: 13.9 GB
总内存: 16 GB
可用内存: 2.1 GB
```

### 磁盘监控

**指标**:
- 磁盘使用量 (字节)
- 总磁盘空间 (字节)
- 磁盘使用率 (%)

**告警条件**:
- 磁盘使用率 > 90% 时发送严重告警
- 磁盘使用率 > 95% 时发送紧急告警

**示例**:

```
磁盘使用率: 92.1%
已用空间: 461 GB
总空间: 500 GB
剩余空间: 39 GB
```

### 应用健康检查

**指标**:
- 应用状态 (健康/不健康)
- 响应时间 (毫秒)
- 应用运行时间 (秒)

**告警条件**:
- 应用无响应或响应超时 > 5秒 时发送严重告警
- 应用返回非200状态码 时发送严重告警

**示例**:

```
应用状态: 健康
响应时间: 125ms
应用运行时间: 86400秒 (1天)
```

### 数据库连接监控

**指标**:
- 数据库连接状态 (已连接/断开)
- 连接响应时间 (毫秒)
- 连接池大小

**告警条件**:
- 数据库无法连接 时发送严重告警
- 连接响应时间 > 1秒 时发送警告告警

**示例**:

```
数据库状态: 已连接
响应时间: 45ms
连接池大小: 10
```

## 告警规则

### 告警级别

| 级别 | 说明 | 触发条件 | 通知方式 |
|------|------|---------|---------|
| 🔵 信息 | 信息性消息 | 系统事件 | 日志 |
| 🟡 警告 | 需要关注 | CPU/内存 > 80% | 邮件 + Slack |
| 🔴 严重 | 需要立即处理 | 磁盘 > 90% / 应用崩溃 | 邮件 + Slack + 企业微信 |

### 告警规则表

```
┌──────────────────────────────────────────────────────────────┐
│                      告警规则评估                             │
├──────────────────────────────────────────────────────────────┤
│ 指标                    │ 警告阈值 │ 严重阈值 │ 告警级别      │
├─────────────────────────┼──────────┼──────────┼──────────────┤
│ CPU使用率               │ 80%      │ 95%      │ 警告/严重    │
│ 内存使用率              │ 85%      │ 95%      │ 警告/严重    │
│ 磁盘使用率              │ 85%      │ 95%      │ 警告/严重    │
│ 应用响应时间            │ 2秒      │ 5秒      │ 警告/严重    │
│ 数据库连接响应时间      │ 500ms    │ 1秒      │ 警告/严重    │
│ 应用健康状态            │ N/A      │ 不健康   │ 严重        │
│ 数据库连接状态          │ N/A      │ 断开     │ 严重        │
└──────────────────────────┴──────────┴──────────┴──────────────┘
```

### 告警去重

相同告警在5分钟内只发送一次，防止告警风暴。

**示例**:

```
时间         | 告警内容              | 是否发送
─────────────┼──────────────────────┼─────────
14:00:00     | CPU使用率过高 (85%)   | ✓ 发送
14:01:00     | CPU使用率过高 (87%)   | ✗ 跳过 (去重)
14:02:00     | CPU使用率过高 (86%)   | ✗ 跳过 (去重)
14:05:30     | CPU使用率过高 (88%)   | ✓ 发送 (5分钟后)
```

## 告警通知

### 邮件通知

**配置**:

```bash
# .env文件
ALERT_EMAIL=admin@company.com
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-email@gmail.com
SMTP_PASS=your-app-password
```

**邮件示例**:

```
主题: [GRT告警] CPU使用率过高

内容:
─────────────────────────────────────────
告警级别: 警告
告警标题: CPU使用率过高
告警时间: 2026-02-05 14:30:00

详情:
CPU使用率: 85.5% (阈值: 80%)
CPU核心数: 8
系统负载: [2.5, 2.3, 2.1]

建议:
1. 检查是否有异常进程占用CPU
2. 考虑增加服务器资源
3. 优化应用性能
─────────────────────────────────────────
```

### Slack通知

**配置**:

1. 创建Slack应用: https://api.slack.com/apps
2. 启用Incoming Webhooks
3. 创建新的Webhook URL
4. 配置环境变量:

```bash
SLACK_WEBHOOK=https://hooks.slack.com/services/YOUR/WEBHOOK/URL
```

**Slack消息示例**:

```
🟡 CPU使用率过高
CPU使用率: 85.5% (阈值: 80%)
时间: 2026-02-05 14:30:00
```

### 企业微信通知

**配置**:

1. 在企业微信中创建机器人
2. 获取Webhook URL
3. 配置环境变量:

```bash
WECHAT_WEBHOOK=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=YOUR_KEY
```

**企业微信消息示例**:

```
🟡 **CPU使用率过高**

CPU使用率: 85.5% (阈值: 80%)
时间: 2026-02-05 14:30:00

建议立即检查系统状态
```

## 故障排查

### 常见问题

#### 问题1: 监控服务无法启动

```bash
# 检查日志
pm2 logs grt-monitor --err

# 检查环境变量
pm2 show grt-monitor | grep env

# 手动运行测试
node scripts/monitoring-service.js
```

#### 问题2: 告警通知未收到

```bash
# 检查邮件配置
cat .env | grep SMTP

# 测试邮件连接
node scripts/test-email.js

# 检查告警日志
cat logs/monitoring/alerts.log
```

#### 问题3: 虚假告警

```bash
# 调整告警阈值
# .env文件
CPU_THRESHOLD=85  # 从80增加到85

# 重启监控服务
pm2 restart grt-monitor
```

#### 问题4: 监控服务占用过多资源

```bash
# 增加监控间隔
MONITOR_INTERVAL=120000  # 从60秒增加到120秒

# 重启监控服务
pm2 restart grt-monitor
```

### 调试模式

```bash
# 启用调试日志
DEBUG=grt:* pm2 start ecosystem.config.js --only grt-monitor

# 查看详细日志
pm2 logs grt-monitor --raw
```

## 最佳实践

### 告警阈值设置

1. **CPU阈值**: 根据应用特性设置
   - 计算密集型: 70-80%
   - I/O密集型: 80-90%

2. **内存阈值**: 预留缓冲空间
   - 生产环境: 85%
   - 测试环境: 90%

3. **磁盘阈值**: 保留足够空间
   - 生产环境: 85-90%
   - 测试环境: 90-95%

### 告警响应流程

```
告警发送
  ↓
接收通知 (邮件/Slack/企业微信)
  ↓
登录仪表板查看详情
  ↓
分析根本原因
  ↓
执行修复操作
  ↓
验证问题解决
  ↓
记录事件报告
```

### 定期维护

- **每周**: 检查告警历史，分析趋势
- **每月**: 优化告警阈值，清理日志
- **每季度**: 性能基准测试，容量规划
