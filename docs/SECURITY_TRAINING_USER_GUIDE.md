## 培训概述

本培训指南帮助GRT团队成员理解和遵守企业级的安全政策，特别是**数据泄露防护（DLP）政策**和**项目生命周期安全检查点**。

### 为什么需要安全培训？

在当今的商业环境中，数据是企业最宝贵的资产。GRT智能系统处理的数据包括：

- **客户信息**: 联系方式、需求、合同条款
- **技术方案**: BOM表、CAD文件、设计文档
- **商业数据**: 价格、成本、利润率
- **项目信息**: 时间表、资源分配、风险评估

这些数据的泄露可能导致：

- **商业损失**: 竞争对手获得商业机密
- **法律风险**: 违反数据保护法规
- **声誉损害**: 客户信任下降
- **运营中断**: 系统被攻击或勒索

### 培训目标

完成本培训后，您将能够：

- 理解GRT的安全架构和DLP政策
- 正确导出邮件和文件而不违反安全政策
- 准备项目生命周期检查所需的文件
- 识别潜在的安全风险
- 在遇到安全问题时正确处理

## 安全基础知识

### GRT安全架构

GRT智能系统采用**零信任网络架构**，这意味着：

**零信任原则**：系统不假设任何用户或设备是可信的，所有访问都需要验证和授权。

| 原则 | 说明 | 实现方式 |
|------|------|--------|
| **验证** | 每个用户都需要身份验证 | 使用用户名和密码登录 |
| **授权** | 每个操作都需要权限检查 | 根据角色分配权限 |
| **审计** | 所有操作都被记录 | 审计日志记录每次访问 |
| **隔离** | 不同的数据被隔离存储 | 按项目/客户隔离数据 |

### 防御深度策略

GRT采用**分层防御**策略，多个安全层次相互配合：

```
┌─────────────────────────────────────────────────┐
│  第1层：网络安全 (Tailscale VPN)                │
│  - 只有授权设备可以访问系统                      │
└─────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────┐
│  第2层：身份认证 (用户名/密码)                  │
│  - 验证用户身份                                  │
└─────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────┐
│  第3层：访问控制 (角色权限)                      │
│  - 根据角色分配权限                              │
└─────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────┐
│  第4层：数据保护 (DLP政策)                       │
│  - 防止敏感数据泄露                              │
└─────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────┐
│  第5层：审计监控 (日志记录)                      │
│  - 记录所有操作                                  │
└─────────────────────────────────────────────────┘
```

### 敏感数据分类

GRT系统中的敏感数据分为以下几类：

| 分类 | 示例 | 风险等级 | 处理要求 |
|------|------|--------|--------|
| **极密** | 价格矩阵、成本数据、战略计划 | 严重 | 禁止导出，仅在系统内查看 |
| **高密** | BOM表、CAD文件、技术方案 | 高 | 需要审批才能导出 |
| **中密** | 项目时间表、资源分配 | 中 | 可导出给授权人员 |
| **低密** | 公开信息、营销资料 | 低 | 可自由导出 |

### 您的安全责任

作为GRT团队成员，您有以下安全责任：

1. **遵守政策**: 严格遵守DLP政策和检查点要求
2. **保护密码**: 不与他人共享密码，定期更改密码
3. **报告问题**: 发现安全问题时立即报告
4. **参与培训**: 完成所有必需的安全培训
5. **谨慎操作**: 不在公共网络上访问敏感数据

## DLP使用指南

### 什么是DLP？

**DLP（数据泄露防护）** 是一套技术和流程，用于防止敏感数据被未授权地访问或导出。

DLP系统通过以下方式工作：

1. **识别**: 识别邮件或文件中的敏感数据
2. **分析**: 分析数据的敏感程度
3. **决策**: 根据政策决定是否允许导出
4. **记录**: 记录所有导出操作

### 邮件导出规则

#### 规则1：CRM白名单检查

**规则**: 邮件只能发送给CRM中已记录的联系人。

**工作原理**:
- 系统检查邮件收件人
- 验证收件人是否在CRM中
- 如果在白名单中，允许发送
- 如果不在白名单中，拒绝发送

**示例**:

| 场景 | 收件人 | 在CRM中 | 结果 |
|------|--------|--------|------|
| 发送给客户 | customer@example.com | ✓ 是 | ✓ 允许 |
| 发送给新联系人 | newperson@example.com | ✗ 否 | ✗ 拒绝 |
| 发送给同事 | colleague@company.com | ✓ 是 | ✓ 允许 |

**操作步骤**:

```
1. 打开邮件客户端
2. 撰写邮件
3. 添加收件人
4. 系统自动检查收件人
5. 如果收件人不在CRM中：
   - 系统显示警告
   - 您可以选择：
     a) 取消发送
     b) 将收件人添加到CRM
     c) 请求管理员批准
6. 发送邮件
```

#### 规则2：内容检查

**规则**: 邮件内容不能包含极密数据（价格、成本等）。

**检查内容**:
- 价格信息（例如：$10,000）
- 成本数据（例如：成本率50%）
- 内部代码（例如：PROJECT_CODE_12345）
- 敏感关键词（例如：机密、绝密）

**示例**:

| 邮件内容 | 包含敏感数据 | 结果 |
|---------|-----------|------|
| "请见附件的项目时间表" | 否 | ✓ 允许 |
| "客户报价为$50,000" | 是（价格） | ✗ 拒绝 |
| "我们的成本是$20,000" | 是（成本） | ✗ 拒绝 |
| "项目编号是GRT-2026-001" | 否 | ✓ 允许 |

**如何处理被拒绝的邮件**:

如果您的邮件被DLP系统拒绝，您有以下选项：

1. **修改内容**: 删除敏感数据后重新发送
2. **请求批准**: 向管理员请求特殊批准
3. **使用其他方式**: 通过电话或面对面会议讨论

### 文件导出规则

#### 规则1：文件类型检查

**支持导出的文件类型**:
- 文本文件: .txt, .md, .doc, .docx
- 表格文件: .xls, .xlsx, .csv
- 演示文件: .ppt, .pptx
- 图像文件: .jpg, .png, .pdf
- 视频文件: .mp4, .avi

**不支持导出的文件类型**:
- 可执行文件: .exe, .bat, .sh
- 压缩文件: .zip, .rar, .7z
- 数据库文件: .db, .sqlite

#### 规则2：文件大小限制

**限制**:
- 单个文件: 最大 500MB
- 批量导出: 最大 2GB
- 每天导出: 最大 10GB

**超过限制的处理**:
- 系统会拒绝导出
- 您可以：
  - 分次导出
  - 请求管理员批准
  - 联系IT支持

#### 规则3：内容检查

**检查项**:
- 文件名中的敏感词
- 文件内容中的敏感数据
- 文件元数据中的敏感信息

**示例**:

| 文件名 | 包含敏感数据 | 结果 |
|--------|-----------|------|
| 项目时间表.xlsx | 否 | ✓ 允许 |
| 价格矩阵.xlsx | 是（价格） | ✗ 拒绝 |
| BOM表_GRT-2026.xlsx | 否 | ✓ 允许 |
| 成本分析.xlsx | 是（成本） | ✗ 拒绝 |

### 常见导出场景

#### 场景1：导出客户报价

**需求**: 向客户发送报价单

**步骤**:
1. 在GRT系统中生成报价单
2. 选择"导出"
3. 系统检查：
   - 收件人是否在CRM中 ✓
   - 内容是否包含敏感数据 ✗（报价包含价格）
4. 系统拒绝导出
5. 您的选项：
   - 请求管理员批准（推荐）
   - 手动删除价格后导出（不推荐）

#### 场景2：导出项目文档

**需求**: 将项目文档导出给项目团队

**步骤**:
1. 选择要导出的文件
2. 系统检查：
   - 文件类型是否支持 ✓
   - 文件大小是否超限 ✓
   - 内容是否包含敏感数据 ✓
3. 系统允许导出
4. 导出成功

#### 场景3：导出给新客户

**需求**: 向新客户发送技术方案

**步骤**:
1. 撰写邮件并附加方案文件
2. 系统检查：
   - 收件人是否在CRM中 ✗（新客户）
   - 内容是否包含敏感数据 ✓
3. 系统拒绝发送
4. 您的选项：
   - 先将客户添加到CRM
   - 请求管理员批准
   - 通过其他渠道发送

### 导出被拒绝时的处理

如果您的导出被DLP系统拒绝，请按以下步骤处理：

**第1步：了解拒绝原因**

系统会显示拒绝原因，例如：
- "收件人不在CRM白名单中"
- "邮件包含敏感数据（价格）"
- "文件大小超过限制"

**第2步：选择处理方式**

根据拒绝原因选择：

| 原因 | 处理方式 |
|------|--------|
| 收件人不在CRM中 | 添加到CRM 或 请求批准 |
| 包含敏感数据 | 修改内容 或 请求批准 |
| 文件大小超限 | 分次导出 或 请求批准 |
| 文件类型不支持 | 转换格式 或 请求批准 |

**第3步：请求批准（如需要）**

如果需要请求批准：

1. 点击"请求批准"按钮
2. 填写申请表：
   - 申请人
   - 申请原因
   - 收件人/导出目标
   - 文件内容描述
3. 提交申请
4. 等待管理员审批（通常24小时内）
5. 审批通过后重新导出

## 项目生命周期安全检查点

### 什么是安全检查点？

**安全检查点** 是项目生命周期中的关键节点，用于确保项目符合安全和合规要求。

GRT项目从M0（销售提案）到M12（交付验收）的12个月中，有多个检查点：

```
M0 销售提案 → M2 项目立项 → M4 设计合规 → M6 采购安全
    ↓             ↓            ↓             ↓
  检查点1       检查点2       检查点3       检查点4
    ↓             ↓            ↓             ↓
M8 实施网络 → M10 测试验证 → M12 交付审计
    ↓             ↓             ↓
  检查点5       检查点6       检查点7
```

### 各阶段检查点详解

#### M0 - 销售提案检查点

**时间**: 项目启动前  
**责任人**: 销售经理  
**检查内容**:

| 检查项 | 说明 | 文件 |
|--------|------|------|
| **客户信息** | 客户是否已添加到CRM | CRM记录 |
| **保密协议** | 是否签署NDA | NDA合同 |
| **初步方案** | 是否有初步技术方案 | 方案文档 |
| **风险评估** | 是否进行初步风险评估 | 风险表 |

**检查清单**:
- [ ] 客户信息完整（名称、联系方式、地址）
- [ ] NDA已签署
- [ ] 初步方案已准备
- [ ] 风险评估已完成
- [ ] 所有文件已上传到系统

**常见问题**:
- Q: 如果客户拒绝签署NDA怎么办？

### 检查点流程

**标准流程**:

```
1. 准备阶段
   ↓
2. 文件上传
   ↓
3. 系统检查
   ↓
4. 管理员审批
   ↓
5. 通过/失败
   ↓
6. 反馈和改进
```

**详细步骤**:

| 步骤 | 操作 | 时间 |
|------|------|------|
| 1. 准备 | 收集所有检查所需的文件 | 1-3天 |
| 2. 上传 | 将文件上传到系统 | 1小时 |
| 3. 检查 | 系统自动检查文件完整性 | 1小时 |
| 4. 审批 | 管理员审批检查结果 | 1-2天 |
| 5. 结果 | 获得通过或失败通知 | 即时 |
| 6. 改进 | 如果失败，改进后重新提交 | 1-3天 |

### 检查失败处理

如果检查失败，系统会显示失败原因。常见的失败原因包括：

| 原因 | 解决方案 |
|------|--------|
| 文件缺失 | 准备缺失的文件 |
| 文件格式错误 | 转换为正确的格式 |
| 内容不完整 | 补充缺失的内容 |
| 不符合标准 | 按标准修改内容 |

**处理步骤**:

1. 查看失败原因
2. 准备改进方案
3. 修改相关文件
4. 重新上传
5. 再次提交检查
6. 等待审批结果

## 常见问题

### Q1: 如果我不小心导出了敏感数据怎么办？

**A**: 立即采取以下行动：

1. **停止传播**: 如果已发送，立即通知收件人删除
2. **报告**: 向安全团队报告此事件
3. **记录**: 记录发生的时间、内容和收件人
4. **改进**: 参与调查并改进流程

安全团队会：
- 调查数据是否被进一步传播
- 评估数据泄露的影响
- 制定改进措施
- 提供后续培训

### Q2: 为什么我的邮件被拒绝了？

**A**: 常见原因：

1. **收件人不在CRM中**: 将收件人添加到CRM或请求批准
2. **邮件包含敏感数据**: 修改邮件内容或请求批准
3. **文件大小超限**: 分次发送或请求批准
4. **系统故障**: 联系IT支持

### Q3: 我可以与外部人员分享GRT的信息吗？

**A**: 根据以下规则：

- **公开信息**: 可以分享（例如营销资料）
- **客户相关信息**: 只能与该客户分享
- **敏感数据**: 不能分享（需要特殊批准）
- **机密信息**: 绝对不能分享

### Q4: 检查点失败了怎么办？

**A**: 按以下步骤处理：

1. 查看失败原因
2. 准备改进方案
3. 修改相关文件
4. 重新提交检查

## 应急处理

### 数据泄露应急流程

如果您发现或怀疑数据泄露，请立即采取行动：

**第1步：停止传播** (立即)
- 停止任何进一步的数据传输
- 通知收件人删除数据
- 记录发生的时间和内容

**第2步：报告** (5分钟内)
- 向直属上司报告
- 向安全团队报告
- 填写事件报告表

**第3步：配合调查** (24小时内)
- 提供所有相关信息
- 配合安全团队的调查
- 参与改进措施的制定

**第4步：后续跟进** (持续)
- 接受额外培训
- 改进工作流程
- 定期检查改进效果

### 系统故障处理

如果系统出现故障（例如无法登录、导出失败等）：

**第1步：尝试重启**
- 刷新浏览器
- 清除浏览器缓存
- 重新登录

**第2步：检查网络**
- 确保网络连接正常
- 检查是否连接到VPN
- 尝试其他网络

**第3步：联系IT支持**
- 提供错误信息
- 描述操作步骤
- 提供屏幕截图
