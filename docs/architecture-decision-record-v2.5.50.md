# GRT智能系统架构决策记录 (ADR-2025-01-30)

## 决策摘要

**决策日期**: 2025年1月30日  
**决策者**: GRT技术团队  
**状态**: 已批准

## 背景

GRT智能系统在开发过程中经历了架构演变：
- **规划阶段** (v1.0-v2.0): 基于NocoBase低代码平台的架构设计
- **实施阶段** (v2.1-v2.5): 实际采用Drizzle ORM + tRPC + React技术栈

经过v2.5.49架构评估，发现：
1. NocoBase从未实际部署，所有相关内容仅存在于规划文档中
2. 当前系统已完整实现243个数据库表、60个API路由、110个前端页面
3. 存在1268个TypeScript编译错误，主要是字段名不匹配和异步调用问题

## 决策

### 1. 架构方向确认

**正式确认继续使用 Drizzle ORM + tRPC + React 架构**

理由：
- 已有完整的功能实现，迁移成本高（估计3-6个月）
- 当前架构满足业务需求
- 团队已熟悉现有技术栈

### 2. 技术栈定义

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端框架 | React 19 + TypeScript | 组件化UI开发 |
| 样式系统 | Tailwind CSS 4 + shadcn/ui | 现代化设计系统 |
| 状态管理 | TanStack Query + tRPC | 类型安全的数据获取 |
| 后端框架 | Express 4 + tRPC 11 | 端到端类型安全 |
| 数据库ORM | Drizzle ORM | 类型安全的SQL构建 |
| 数据库 | MySQL/TiDB | 关系型数据存储 |
| 认证系统 | Manus OAuth | 统一身份认证 |

### 3. AI工具角色分工

| 工具 | 角色 | 职责 |
|------|------|------|
| **Manus** | 规划与协调 | 任务规划、进度跟踪、质量验证、文档生成 |
| **Claude Code** | 实现与开发 | 代码编写、bug修复、功能实现 |
| **Gemini** | 分析与建议 | 业务分析、技术建议、AI功能集成 |

### 4. NocoBase文档处理

- 将所有NocoBase规划文档标记为"历史参考"
- 提取文档中的业务需求和设计理念
- 基于新技术栈重新创建开发指南

## 影响

### 正面影响
- 明确技术方向，减少架构混乱
- 保留已有功能投资
- 统一开发规范和流程

### 需要解决的问题
- 修复1268个TypeScript编译错误
- 更新开发文档和指南
