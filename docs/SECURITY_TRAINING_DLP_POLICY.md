## 概述

**数据泄露防护（DLP）** 是GRT智能系统的核心安全机制，旨在防止敏感信息（如BOM表、价格矩阵、CAD设计文件）通过邮件、文件导出等方式泄露给未授权人员。

### 核心目标

- **防止意外泄露**: 拦截包含敏感数据的邮件和文件导出
- **审计追踪**: 记录所有数据访问和导出活动
- **合规保证**: 确保符合ISO 27001、SOC 2等安全标准
- **用户赋能**: 提供清晰的使用指南，帮助员工正确处理敏感数据

### 关键特性

| 特性 | 说明 |
|------|------|
| **自动检测** | 使用正则表达式和模式匹配自动识别敏感数据 |
| **多层验证** | 邮箱白名单、内容审计、文件类型检查三层防护 |
| **智能去重** | 避免重复告警，提高告警有效性 |
| **完整审计** | 记录所有操作，支持事后追溯和调查 |
| **灵活配置** | 支持自定义规则和阈值，适应不同业务场景 |

### 工作流程

1. **用户操作**: 用户尝试导出邮件或文件
2. **白名单检查**: 系统验证用户邮箱是否在CRM白名单中
3. **内容审计**: 系统扫描内容中的敏感数据模式
4. **风险评估**: 根据检测到的敏感数据数量判断风险级别
5. **决策**: 允许、警告或拒绝操作
6. **记录**: 将所有操作记录到审计日志

## 敏感数据分类

### 识别模式

DLP系统使用以下模式识别敏感数据：

| 数据类型 | 模式示例 | 风险等级 | 说明 |
|---------|---------|--------|------|
| **BOM表** | "BOM", "物料清单", "bill of materials" | 高 | 产品物料清单，包含供应链信息 |
| **价格信息** | "价格", "price", "¥", "$", "成本" | 中 | 产品或服务价格，涉及商业机密 |
| **CAD文件** | ".dwg", ".dxf", ".step", ".iges" | 高 | 设计文件，包含产品设计信息 |
| **IP地址** | "192.168.x.x", "10.x.x.x" | 中 | 内部网络配置信息 |
| **电子邮件** | "name@company.com", "user@domain.com" | 低 | 个人联系信息 |
| **电话号码** | "+86 1X XXXX XXXX", "010-XXXX-XXXX" | 低 | 个人联系方式 |
| **身份证号** | "XXX-XX-XXXX" | 高 | 个人身份信息 |

### 风险等级定义

| 等级 | 检测数据数量 | 处理方式 | 说明 |
|-----|-----------|--------|------|
| **低** | 0个 | 允许 | 无敏感数据，正常处理 |
| **中** | 1个 | 允许+警告 | 单个敏感数据，记录但允许 |
| **高** | 2-3个 | 警告+审查 | 多个敏感数据，需要审查 |
| **严重** | 4个以上 | 拒绝 | 过多敏感数据，自动拒绝 |

## 政策框架

### 1. CRM白名单政策

#### 目的
确保只有授权的CRM人员可以导出包含敏感数据的邮件。

#### 白名单成员
- 销售部门: sales@company.com
- CRM管理员: crm@company.com
- 系统管理员: admin@company.com
- 其他授权人员: 由CRM管理员添加

#### 申请流程
1. 员工向CRM管理员提交申请
2. 提供申请理由和业务需求
3. CRM管理员审批（通常24小时内）
4. 批准后添加到白名单
5. 员工收到确认邮件

### 2. 内容审计政策

#### 目的
自动识别和标记包含敏感数据的邮件和文件。

#### 审计规则
- **自动扫描**: 所有导出操作自动扫描内容
- **模式匹配**: 使用正则表达式识别已知敏感数据
- **风险评分**: 根据敏感数据数量计算风险分数
- **实时反馈**: 用户立即收到审计结果

#### 审计日志内容
- 操作时间和用户
- 操作类型（邮件导出/文件导出）
- 检测到的敏感数据类型
- 风险等级
- 操作结果（允许/拒绝/警告）

### 3. 邮件导出政策

#### 允许条件
✓ 发送者在CRM白名单中  
✓ 收件人邮箱格式有效  
✓ 邮件内容风险等级不超过"高"  

#### 拒绝条件
✗ 发送者不在CRM白名单中  
✗ 收件人邮箱格式无效  
✗ 邮件内容风险等级为"严重"  

#### 示例场景

**场景1: 允许导出**
```
发送者: sales@company.com (在白名单中)
收件人: customer@client.com (有效邮箱)
内容: "Please see the price: $100"
风险等级: 中
结果: ✓ 允许导出 (记录为中等风险)
```

**场景2: 警告但允许**
```
发送者: sales@company.com
收件人: supplier@vendor.com
内容: "BOM表已更新，价格为¥5000"
风险等级: 高
结果: ⚠ 允许导出 (记录为高风险，发送警告)
```

**场景3: 拒绝导出**
```
发送者: john.doe@company.com (不在白名单中)
收件人: external@unknown.com
内容: 任何内容
结果: ✗ 拒绝导出 (用户无权导出邮件)
```

### 4. 文件导出政策

#### 允许的文件类型
- .xlsx (Excel)
- .csv (逗号分隔值)
- .pdf (便携式文档)
- .txt (纯文本)
- .json (JSON数据)

#### 文件大小限制
- 最大100MB
- 超过限制自动拒绝

#### 内容检查
- 自动扫描文件内容
- 检测敏感数据
- 根据风险等级决策

#### 示例场景

**场景1: 允许导出**
```
文件名: sales_report_2026.xlsx
文件大小: 5MB
内容: 销售数据（无敏感信息）
结果: ✓ 允许导出
```

**场景2: 拒绝导出**
```
文件名: bom_with_prices.xlsx
文件大小: 10MB
内容: BOM表 + 价格 + CAD链接 + IP地址
风险等级: 严重
结果: ✗ 拒绝导出 (敏感数据过多)
```

## 使用指南

### 对于销售人员

#### 如何正确导出邮件

1. **检查邮件内容**
   - 确认邮件中不包含BOM表、CAD文件链接或价格信息
   - 如果包含，请删除或替换为通用表述

2. **确认收件人**
   - 验证收件人邮箱地址正确
   - 确认收件人是授权的客户或合作伙伴

3. **执行导出**
   - 点击"导出"按钮
   - 系统自动进行安全检查
   - 如果通过，邮件被导出；如果失败，查看错误信息

4. **处理警告**
   - 如果收到"中等风险"警告，可以继续导出
   - 系统会记录此操作以供审计

#### 如何正确导出文件

1. **准备文件**
   - 使用允许的格式（.xlsx, .csv, .pdf, .txt, .json）
   - 确保文件大小不超过100MB
   - 删除或替换敏感数据

2. **检查文件内容**
   ```
   ✓ 允许: 销售数据、客户信息、通用报告
   ✗ 禁止: BOM表、价格矩阵、CAD文件、IP地址
   ```

3. **执行导出**
   - 选择文件
   - 点击"导出"
   - 等待系统检查
   - 查看结果

### 对于运维人员

#### 监控DLP系统

1. **日常检查**
   - 每天检查审计日志
   - 查看是否有异常导出尝试
   - 监控告警数量和趋势

2. **处理拒绝的操作**
   - 查看被拒绝的导出请求
   - 联系相关用户了解原因
   - 如果合理，可以临时调整规则

3. **定期报告**
   - 每周生成合规报告
   - 统计导出次数、风险等级分布
   - 识别高风险用户或操作

#### 管理白名单

1. **添加新成员**
   ```
   步骤:
   1. 验证申请人身份
   2. 确认业务需求
   3. 在管理界面添加邮箱
   4. 发送确认邮件
   ```

2. **移除成员**
   ```
   步骤:
   1. 验证移除原因
   2. 通知相关人员
   3. 在管理界面删除邮箱
   4. 记录移除原因
   ```

#### 调整敏感数据规则

1. **添加新的敏感模式**
   ```
   例如: 添加新的产品代码模式
   - 模式: "PROD-\d{4}-\d{2}"
   - 风险等级: 中
   - 说明: 内部产品代码
   ```

2. **修改现有规则**
   ```
   例如: 调整价格识别的敏感性
   - 原规则: 包含"¥"或"$"
   - 新规则: 仅识别"¥XXXXX"或"$XXXXX"
   ```

### 对于安全团队

#### 审计和合规

1. **定期审计**
   - 每月审查完整的审计日志
   - 检查是否有绕过DLP的尝试
   - 分析高风险操作的原因

2. **生成合规报告**
   ```
   报告内容:
   - 总导出次数
   - 被拒绝的导出次数
   - 高风险操作数量
   - 异常活动分析
   - 建议和改进措施
   ```

3. **事件调查**
   - 如果发现可疑活动，立即调查
   - 收集相关证据
   - 与相关部门沟通
   - 记录调查结果

#### 应急响应

1. **检测到数据泄露**
   ```
   立即行动:
   1. 隔离受影响的账户
   2. 收集所有相关日志
   3. 通知管理层
   4. 启动应急响应流程
   ```

2. **系统故障**
   ```
   如果DLP系统故障:
   1. 立即切换到备份系统
   2. 通知所有用户
   3. 禁止导出操作
   4. 进行故障排查
   ```

## 应急响应

### 数据泄露事件流程

```
发现泄露
    ↓
立即隔离账户
    ↓
收集证据和日志
    ↓
评估泄露范围
    ↓
通知管理层
    ↓
启动调查
    ↓
制定补救措施
    ↓
实施修复
    ↓
事后总结
```

### 常见应急场景

#### 场景1: 敏感邮件被意外导出

**症状**: 用户报告敏感邮件被导出

**响应步骤**:
1. 立即检查审计日志确认导出时间和内容
2. 联系收件人要求删除邮件
3. 调查为什么DLP未拦截（系统故障或规则漏洞）
4. 更新规则或修复故障
5. 向管理层报告

#### 场景2: 用户尝试绕过DLP

**症状**: 用户多次尝试导出被拒绝的内容

**响应步骤**:
1. 查看审计日志中的所有尝试
2. 联系用户了解原因
3. 如果是合理需求，评估是否需要调整规则
4. 如果是恶意行为，升级为安全事件
5. 记录所有操作

#### 场景3: DLP系统被禁用或篡改

**症状**: 审计日志中出现异常或系统配置被修改

**响应步骤**:
1. 立即启动应急响应
2. 隔离受影响的系统
3. 恢复到已知安全状态
4. 进行完整的安全审计
5. 加强访问控制

## 常见问题

### Q1: 如何申请加入CRM白名单？

**A**: 请向CRM管理员（crm@company.com）发送邮件，包含以下信息：
- 您的邮箱地址
- 申请理由
- 业务需求描述

通常会在24小时内获得批准。

### Q2: 如果我的邮件被拒绝，该怎么办？

**A**: 
1. 检查错误信息了解拒绝原因
2. 如果是内容问题，删除敏感数据后重试
3. 如果是权限问题，申请加入白名单
4. 如果问题仍未解决，联系运维团队

### Q3: 为什么我的文件导出被拒绝？

**A**: 可能的原因：
- 文件格式不支持（仅支持.xlsx, .csv, .pdf, .txt, .json）
- 文件大小超过100MB
- 文件内容包含过多敏感数据

请根据错误信息调整文件后重试。

### Q4: 我可以导出包含价格信息的邮件吗？

**A**: 如果您在CRM白名单中，可以导出包含单个敏感数据（如价格）的邮件，但系统会记录为"中等风险"。如果邮件包含多个敏感数据（如BOM + 价格 + CAD文件），则会被拒绝。

### Q5: 审计日志会保留多长时间？

**A**: 审计日志会保留至少2年，以满足合规要求。具体保留时间由安全团队决定。

### Q6: 如果我认为某个规则不合理，可以修改吗？

**A**: 不能直接修改。请向安全团队提交建议，包含：
- 具体的规则
- 修改理由
- 业务影响
- 建议的修改方案

安全团队会评估并决定是否修改。

### Q7: DLP系统会影响性能吗？

**A**: DLP检查非常快速（通常< 100ms），对用户体验的影响微乎其微。

### Q8: 如何查看我的导出历史？

**A**: 您可以在个人仪表板中查看导出历史。如果需要详细的审计日志，请向安全团队申请。
