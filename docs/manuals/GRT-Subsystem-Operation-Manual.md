## 1. MES制造执行系统

### 1.1 系统概述

MES（Manufacturing Execution System）制造执行系统是GRT智能系统的核心生产管理模块，负责从项目立项到产品交付的全生命周期管理。该系统基于NocoBase低代码平台构建，通过Claude Code实现业务逻辑的自动化处理。

MES系统覆盖五大事业部的生产管理需求：海外事业部（BU-OVERSEAS）、商用车事业部（BU-CV）、乘用车事业部（BU-PV）、机加工事业部（BU-MACHINING）以及第十事业部（BU-10）。每个事业部可独立配置生产流程，同时共享统一的物料编码和BOM管理体系。

### 1.2 前期输入内容要求

在启用MES系统前，需要准备以下基础数据：

| 数据类别 | 具体内容 | 数据格式 | 责任部门 |
|---------|---------|---------|---------|
| 组织架构 | 事业部信息、角色定义、人员分配 | JSON/Excel | 人力资源部 |
| 物料主数据 | SKU编码、物料描述、计量单位、安全库存 | Excel模板 | 研发部/采购部 |
| BOM结构 | 父项/子项关系、用量、版本号 | Excel/系统导入 | 研发部 |
| 供应商信息 | 供应商编码、联系方式、评级、资质证书 | Excel模板 | 采购部 |
| 工艺路线 | 工序定义、标准工时、设备要求 | 系统配置 | 生产部 |

**物料编码规则示例**：
```
格式：[类别码]-[规格码]-[流水号]
示例：PUMP-DN50-001（泵类-DN50规格-第001号）
```

### 1.3 操作步骤与流程

#### 1.3.1 项目创建流程

**步骤一：项目立项**

项目经理在系统中创建新项目时，需填写以下信息：项目编码（系统自动生成，格式为P-YYYY-NNN）、项目名称、客户信息、合同金额、付款条款（选择3-3-3-1或4-5-1等预设模板）、计划开始日期和计划完成日期。系统将自动关联该项目所属的事业部，并初始化M0-M12门径状态。

**步骤二：BOM导入与确认**

研发工程师从历史项目中选择相似BOM作为模板，或通过AI建议功能获取推荐BOM结构。系统支持三种BOM处理方式：完全采用AI建议、部分修改后采用、完全重新编制。确认后的BOM将锁定版本号，后续修改需通过ECN（工程变更通知）流程。

**步骤三：任务卡分解**

生产计划员根据BOM和工艺路线，将项目分解为具体的任务卡。每张任务卡包含：任务类型（机架装配、管路安装、电气接线、调试等）、计划工时、责任人、前置任务依赖关系。系统自动计算关键路径并生成甘特图。

#### 1.3.2 生产执行流程

**步骤一：任务领取**

技师通过移动端扫描任务卡二维码领取任务，系统记录领取时间并自动开始计时。领取时需确认物料齐套状态，如有缺料系统将触发预警。

**步骤二：工时记录**

技师在执行过程中可通过以下方式记录工时：手动点击开始/暂停/完成按钮、扫描工位二维码自动打卡、UWB定位自动采集（需部署UWB基站）。系统实时计算实际工时与计划工时的偏差，超标时自动预警。

**步骤三：质量检验**

完成装配后，质检员执行检验并在系统中记录结果。检验项目包括：尺寸检验、功能测试、外观检查等。不合格项需填写不合格原因并触发返工流程。

**步骤四：进度更新**

系统自动汇总各任务卡的完成状态，更新生产进度看板。看板展示：整体完成率、各工序进度、延期任务列表、资源负荷情况。

### 1.4 执行效果与预期产出

| 效果指标 | 预期目标 | 测量方法 |
|---------|---------|---------|
| 工时准确率 | ≥95% | 实际工时/计划工时 |
| 物料齐套率 | ≥98% | 齐套任务数/总任务数 |
| 一次合格率 | ≥90% | 首次检验合格数/总检验数 |
| 交付准时率 | ≥95% | 准时交付项目数/总项目数 |
| 库存周转率 | 提升20% | 年销售成本/平均库存 |

## 2. AI赋能采购系统

### 2.1 系统概述

AI赋能采购系统是GRT智能系统的智能化采购管理模块，通过集成Manus AI能力，实现询价自动化、价格智能分析、供应商风险评估等功能。该系统支持中英德三语询价，满足海外事业部的国际采购需求。

### 2.2 前期输入内容要求

| 数据类别 | 具体内容 | 数据格式 | 责任部门 |
|---------|---------|---------|---------|
| 供应商库 | 供应商基本信息、历史报价、交付记录 | 系统维护 | 采购部 |
| 物料需求 | 采购申请单、BOM展开需求 | 系统生成 | 生产部/研发部 |
| 价格基准 | 历史成交价、目标价格、预算上限 | Excel/系统 | 采购部/财务部 |
| 邮件模板 | 询价邮件模板（中/英/德） | 系统配置 | 采购部 |

### 2.3 操作步骤与流程

#### 2.3.1 AI自动询价流程

**步骤一：创建询价单**

采购员在系统中创建RFQ（Request for Quotation），选择需要询价的物料清单。系统自动关联该物料的合格供应商列表，采购员可手动添加或排除特定供应商。

**步骤二：AI生成询价邮件**

系统调用AI引擎，根据物料信息和供应商特点自动生成询价邮件。邮件内容包括：物料规格要求、数量、交货期、付款条款等。系统根据供应商所在地区自动选择语言版本（中文/英文/德文）。

**步骤三：发送与跟踪**

询价邮件通过系统邮件服务发送，系统自动记录发送时间并跟踪供应商回复状态。对于超过3个工作日未回复的供应商，系统自动发送催促邮件。

**步骤四：报价收集与OCR识别**

供应商可通过两种方式提交报价：登录H5报价门户在线填写、回复邮件附带报价单。对于邮件附件中的报价单，系统使用OCR技术自动识别并提取关键信息（单价、交货期、有效期等）。

#### 2.3.2 价格分析与决策流程

**步骤一：AI价格分析**

系统自动汇总所有供应商报价，生成价格分析报告。报告内容包括：最低价/最高价/平均价、价格离散度、与历史价格对比、与目标价格对比。

**步骤二：最佳价值评估**

AI综合考虑以下因素计算最佳价值得分：价格竞争力（权重40%）、交货期（权重20%）、质量历史（权重25%）、服务响应（权重15%）。系统推荐得分最高的供应商作为首选。

**步骤三：风险评估**

系统自动评估三类风险：供应商集中度风险（单一供应商占比超过60%触发预警）、交付风险（基于历史准时交付率）、质量风险（基于历史合格率）。高风险项目需经采购经理审批。

**步骤四：采购决策**

采购员根据AI建议和风险评估结果，选择最终供应商并生成采购订单。订单自动关联付款条款和交货计划。

### 2.4 执行效果与预期产出

| 效果指标 | 预期目标 | 测量方法 |
|---------|---------|---------|
| 询价效率 | 提升70% | 询价周期缩短天数 |
| 采购成本 | 降低5-10% | 实际成交价/预算价 |
| 供应商响应率 | ≥90% | 回复供应商数/询价供应商数 |
| 交付准时率 | ≥95% | 准时交付订单数/总订单数 |

## 3. 3-3-3-1财务管控系统

### 3.1 系统概述

3-3-3-1财务管控系统是GRT智能系统的项目财务管理模块，实现从合同签订到项目结算的全过程财务管控。系统名称来源于GRT最常用的付款条款模式：预付30%、提货30%、发货30%、质保10%。

### 3.2 前期输入内容要求

| 数据类别 | 具体内容 | 数据格式 | 责任部门 |
|---------|---------|---------|---------|
| 付款条款模板 | 3-3-3-1、4-5-1、5-3-2等标准条款 | 系统配置 | 财务部 |
| 成本分类标准 | DM/DL/DE/MO四大类及明细科目 | 系统配置 | 财务部 |
| 预算模板 | 项目预算编制模板 | Excel/系统 | 财务部 |
| 汇率信息 | 多币种汇率（人民币/美元/欧元） | 系统维护 | 财务部 |

### 3.3 操作步骤与流程

#### 3.3.1 项目预算编制流程

**步骤一：预算初始化**

项目立项后，系统自动创建项目预算表。财务人员根据合同金额和历史数据，编制各成本类别的预算：DM（直接材料）、DL（直接人工）、DE（直接费用）、MO（制造费用）。

**步骤二：预算审批**

预算编制完成后提交审批。审批流程根据项目金额自动路由：100万以下由部门经理审批、100-500万由财务总监审批、500万以上由总经理审批。

**步骤三：预算下达**

审批通过后，预算正式下达并锁定。后续所有采购申请、费用报销均需在预算额度内执行。

#### 3.3.2 付款节点管控流程

**步骤一：付款条款配置**

项目创建时选择付款条款模板（如3-3-3-1），系统自动生成付款里程碑：M1-预付款（30%，合同签订后）、M2-提货款（30%，设备出厂前）、M3-发货款（30%，设备到达现场）、M4-质保款（10%，质保期满）。

**步骤二：付款触发与确认**

当项目达到付款节点时，系统自动触发付款申请。销售人员确认客户付款后，在系统中登记收款信息。系统自动更新付款里程碑状态。

**步骤三：业务锁定机制**

未收到对应款项时，系统自动锁定后续业务操作：未收预付款→锁定采购下单、未收提货款→锁定出厂发货、未收发货款→锁定现场安装。锁定状态需财务总监审批后方可解除。

#### 3.3.3 成本实时监控流程

**步骤一：成本归集**

系统自动归集项目相关成本：采购订单金额计入DM、工时记录金额计入DL、差旅报销计入DE、设备折旧计入MO。

**步骤二：预算对比**

系统实时计算预算执行率，生成预算对比报表。报表展示：各类别预算/实际/偏差、整体预算执行率、预计完工成本。

**步骤三：预警与审批**

当实际成本达到预算的80%时触发黄色预警，达到100%时触发红色预警。超预算支出需经过额外审批：超10%以内由项目经理审批、超10-20%由部门经理审批、超20%以上由总经理审批。

### 3.4 执行效果与预期产出

| 效果指标 | 预期目标 | 测量方法 |
|---------|---------|---------|
| 预算准确率 | ≥90% | 实际成本/预算成本 |
| 回款及时率 | ≥95% | 按期回款金额/应收金额 |
| 成本超支率 | ≤5% | 超支项目数/总项目数 |
| 利润率 | ≥15% | 项目利润/项目收入 |

## 4. 门径管理系统

### 4.1 系统概述

门径管理系统是GRT智能系统的项目阶段管控模块，采用M0-M12里程碑体系和H1-H4人力资本门径，确保项目按计划推进并在关键节点进行质量把控。该系统借鉴了Stage-Gate模型的最佳实践，结合GRT业务特点进行了本地化定制。

### 4.2 前期输入内容要求

| 数据类别 | 具体内容 | 数据格式 | 责任部门 |
|---------|---------|---------|---------|
| 门径定义 | M0-M12各阶段定义、检查清单 | 系统配置 | PMO |
| 否决标准 | 各门径的Kill Criteria | 系统配置 | PMO |
| 评审委员会 | 各门径评审人员名单 | 系统维护 | PMO |
| 模板文档 | 各阶段交付物模板 | 文档库 | PMO |

### 4.3 操作步骤与流程

#### 4.3.1 M0-M12里程碑管理流程

**步骤一：门径初始化**

项目创建时，系统自动初始化M0-M12门径状态。各门径定义如下：

| 门径 | 阶段 | 关键交付物 | 是否硬门径 |
|-----|------|-----------|-----------|
| M0 | 商机确认 | 客户需求确认书 | 是 |
| M1 | 方案设计 | 技术方案书 | 否 |
| M2 | 合同签订 | 正式合同 | 是 |
| M3 | 设计启动 | 设计任务书 | 是 |
| M4 | 设计评审 | 设计图纸 | 否 |
| M5 | 设计冻结 | 最终设计文件 | 是 |
| M6 | 采购完成 | 采购订单 | 否 |
| M7 | 生产启动 | 生产计划 | 是 |
| M8 | 装配完成 | 装配报告 | 否 |
| M9 | FAT验收 | FAT报告 | 是 |
| M10 | 发货 | 发货单 | 否 |
| M11 | SAT验收 | SAT报告 | 否 |
| M12 | 项目关闭 | 结项报告 | 是 |

**步骤二：检查清单执行**

每个门径包含若干检查项，分为三类：必须项（Mandatory）、可选项（Optional）、条件项（Conditional）。项目团队逐项完成检查并上传证据文件。

**步骤三：门径评审**

当所有必须项完成后，项目经理发起门径评审申请。系统自动通知评审委员会成员，并生成评审议程。评审结果分为三种：通过（Go）、有条件通过（Conditional Go）、不通过（No Go）。

**步骤四：否决机制**

硬门径评审时，系统自动检查Kill Criteria。触发任一否决标准将强制项目进入红灯状态，需提交指导委员会决策。常见否决标准包括：客户信用评级为D级、技术方案无法满足客户核心需求、预算超支超过30%等。

#### 4.3.2 H1-H4人力资本门径流程

**步骤一：JD结构化**

HR在系统中创建结构化岗位描述，包括：技能要求矩阵（必备/优选/加分）、工作输出定义、关键绩效指标。系统自动生成岗位画像。

**步骤二：面试评估**

面试官在系统中记录面试评估结果，系统自动计算候选人与岗位的匹配度。对于能力Gap项，系统自动生成Gap标签并建议培训计划。

**步骤三：入职KPI生成**

候选人入职后，系统根据JD自动生成试用期KPI建议。主管确认后，KPI正式生效并进入跟踪状态。

### 4.4 执行效果与预期产出

| 效果指标 | 预期目标 | 测量方法 |
|---------|---------|---------|
| 门径通过率 | ≥85% | 一次通过门径数/总门径数 |
| 项目延期率 | ≤10% | 延期项目数/总项目数 |
| 否决准确率 | ≥95% | 正确否决数/总否决数 |
| 人岗匹配度 | ≥80% | 试用期通过人数/入职人数 |

## 5. 工作流引擎系统

### 5.1 系统概述

工作流引擎系统是GRT智能系统的流程自动化模块，提供类似简道云的流程固化能力。该系统支持可视化流程设计、表单构建、审批路由配置，实现业务流程的标准化和自动化。

### 5.2 前期输入内容要求

| 数据类别 | 具体内容 | 数据格式 | 责任部门 |
|---------|---------|---------|---------|
| 流程定义 | 业务流程清单、流程图 | Visio/系统 | 各业务部门 |
| 审批矩阵 | 各类业务的审批层级 | Excel/系统 | 行政部 |
| 表单模板 | 各类业务表单样式 | 系统配置 | IT部 |
| 组织架构 | 部门、岗位、人员关系 | 系统维护 | HR部 |

### 5.3 操作步骤与流程

#### 5.3.1 流程设计流程

**步骤一：创建流程**

流程管理员在WorkflowDesigner中创建新流程，定义流程基本信息：流程名称、流程类别、适用范围、版本号。

**步骤二：设计流程节点**

通过拖拽方式添加流程节点，支持以下节点类型：开始节点（Start）、审批节点（Approval）、抄送节点（CC）、条件分支节点（Condition）、AI决策节点（AI Decision）、结束节点（End）。

**步骤三：配置节点属性**

为每个节点配置详细属性：审批节点需配置审批人（指定人员/角色/部门负责人/上级主管）、审批方式（会签/或签）、超时处理（自动通过/自动拒绝/升级）。条件分支节点需配置分支条件表达式。

**步骤四：发布流程**

流程设计完成后进行测试，测试通过后发布上线。发布后的流程自动生效，旧版本流程中的在途实例继续按原流程执行。

#### 5.3.2 表单构建流程

**步骤一：创建表单**

表单管理员在FormBuilder中创建新表单，定义表单基本信息：表单名称、关联流程、数据存储表。

**步骤二：添加表单字段**

通过拖拽方式添加表单字段，支持以下字段类型：单行文本、多行文本、数字、日期、下拉选择、单选、多选、附件上传、关联数据、计算字段。

**步骤三：配置字段属性**

为每个字段配置详细属性：字段标签、是否必填、默认值、校验规则、显示条件。计算字段需配置计算公式。

**步骤四：配置权限**

配置表单字段在不同流程节点的权限：可见/隐藏、可编辑/只读、必填/选填。

#### 5.3.3 流程执行流程

**步骤一：发起申请**

用户填写表单并提交，系统自动创建流程实例并推送至第一个审批节点。

**步骤二：审批处理**

审批人收到待办通知，查看申请内容后进行审批操作：同意、拒绝、退回、转交。审批时可添加审批意见。

**步骤三：流程流转**

系统根据审批结果和流程定义自动流转：同意则流转至下一节点、拒绝则流程终止、退回则返回指定节点。

**步骤四：流程归档**

流程结束后自动归档，所有审批记录和表单数据永久保存，支持查询和追溯。

### 5.4 执行效果与预期产出

| 效果指标 | 预期目标 | 测量方法 |
|---------|---------|---------|
| 流程覆盖率 | ≥90% | 已固化流程数/总业务流程数 |
| 审批效率 | 提升50% | 平均审批周期缩短比例 |
| 流程合规率 | ≥99% | 合规流程实例数/总实例数 |
| 用户满意度 | ≥85% | 满意用户数/总用户数 |

## 6. 智能人才网格系统

### 6.1 系统概述

智能人才网格系统是GRT智能系统的人力资源管理模块，实现员工技能图谱管理、DA（Digital Assistant）跨岗位逻辑、安全红线规则等功能。该系统通过AI赋能，实现人才的智能匹配和发展规划。

### 6.2 前期输入内容要求

| 数据类别 | 具体内容 | 数据格式 | 责任部门 |
|---------|---------|---------|---------|
| 员工档案 | 基本信息、教育背景、工作经历 | 系统维护 | HR部 |
| 技能字典 | 技能分类、技能等级定义 | 系统配置 | HR部 |
| 资质证书 | 证书类型、有效期、等级 | 系统维护 | HR部 |
| 岗位能力模型 | 各岗位所需技能和等级 | 系统配置 | HR部 |

### 6.3 操作步骤与流程

#### 6.3.1 技能图谱管理流程

**步骤一：技能录入**

员工或HR在系统中录入员工技能信息，包括：技能名称、技能等级（1-5级）、获取时间、证明材料。

**步骤二：技能评估**

主管定期对下属进行技能评估，评估结果自动更新技能图谱。系统支持360度评估模式。

**步骤三：技能差距分析**

系统自动对比员工当前技能与岗位要求，生成技能差距报告。报告包括：达标技能、待提升技能、建议培训课程。

**步骤四：发展规划**

基于技能差距，系统自动生成个人发展计划（IDP），包括：培训计划、轮岗建议、晋升路径。

#### 6.3.2 DA跨岗位逻辑流程

**步骤一：DA初始化**

员工入职时，系统自动为其创建个人DA（Digital Assistant），DA编号格式为{员工ID}-DA。

**步骤二：功能型助手订阅**

系统根据员工岗位自动订阅对应的功能型助手：技术工程师订阅Engineering_Assistant、销售人员订阅Sales_Assistant、财务人员订阅Finance_Assistant。

**步骤三：故障逻辑链继承**

DA自动继承所订阅功能型助手的故障逻辑链，当员工遇到问题时，DA可提供智能引导。

**步骤四：跨岗位协作**

当员工参与跨部门项目时，DA临时订阅相关功能型助手，项目结束后自动取消订阅。

#### 6.3.3 安全红线规则流程

**步骤一：规则配置**

安全管理员在SafetyFilter中配置安全红线规则，包括：物理参数限制（温度、压力、转速等）、材质-参数冲突规则、操作资质要求。

**步骤二：AI建议校验**

当AI生成操作建议时，系统自动调用SafetyFilter进行校验。校验内容包括：参数是否在安全范围内、操作员是否具备相应资质。

**步骤三：拦截与预警**

校验不通过时，系统拦截AI建议并返回错误码：AI_003（数据验证失败）、AI_009（安全规则冲突）、AI_011（操作员资质不足）。同时触发预警通知相关人员。

**步骤四：例外审批**

特殊情况下需突破安全红线时，须经安全主管审批。审批通过后，系统记录例外操作并生成风险提示。

### 6.4 执行效果与预期产出

| 效果指标 | 预期目标 | 测量方法 |
|---------|---------|---------|
| 技能覆盖率 | ≥95% | 已录入技能员工数/总员工数 |
| 人岗匹配度 | ≥85% | 技能达标员工数/总员工数 |
| 安全拦截率 | 100% | 拦截违规操作数/总违规操作数 |
| 培训完成率 | ≥90% | 完成培训人次/计划培训人次 |
