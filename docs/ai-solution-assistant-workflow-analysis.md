# AI方案助理作业流程分析

## 一、当前实现概述

AI方案助理（Solution Assistant）是GRT智能系统的核心AI模块之一，主要用于工业清洗设备的方案设计和推荐。

### 1.1 核心功能模块

| 模块 | 文件位置 | 功能描述 |
|------|----------|----------|
| 方案助手核心 | `server/ai-assistants/solutionAssistant.ts` | 工艺参数解析、方案匹配、持续学习 |
| 报价助手核心 | `server/ai-assistants/quotationAssistant.ts` | 成本计算、价格分析、竞品对比 |
| tRPC路由 | `server/ai-assistants/solutionQuotationRoutes.ts` | API接口定义 |
| 前端界面 | `client/src/pages/AIAssistantHub.tsx` | 用户交互界面 |

### 1.2 已实现的功能

1. **GRT方案优先推荐**：从历史成功案例中优先匹配GRT内部方案
2. **工艺参数处理**：使用LLM解析产品、清洁度、节拍、上下料等参数
3. **同行方案参照**：参考行业方案并标注来源备注
4. **持续学习**：从已交付项目中学习，更新方案成功率
5. **设备关联**：关联设备型号和项目号

## 二、作业流程详解

### 2.1 方案推荐流程

```
用户输入需求
    ↓
┌─────────────────────────────────────┐
│  1. 工艺参数解析 (parseProcessParameters)  │
│  - 使用LLM从自然语言提取结构化参数          │
│  - 提取：工件类型、清洁度、节拍、上下料方式  │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  2. 历史方案检索                           │
│  - 从 historicalSolutions 表查询           │
│  - 优先GRT内部方案 (sourceType=grt_internal)│
│  - 按成功率排序                            │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  3. 相似度计算 (calculateSimilarity)       │
│  - 工件类型匹配 (30%)                      │
│  - 清洁度要求匹配 (25%)                    │
│  - 节拍要求匹配 (20%)                      │
│  - 工件尺寸匹配 (15%)                      │
│  - 特殊要求匹配 (10%)                      │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  4. 方案排序和推荐                         │
│  - GRT内部方案优先                         │
│  - 按相似度分数排序                        │
│  - 返回Top N推荐结果                       │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  5. 工艺流程建议                           │
│  - 根据工件类型推荐标准工艺流程            │
│  - 推荐设备型号                            │
│  - 估算节拍时间                            │
└─────────────────────────────────────┘
    ↓
输出推荐报告
```

### 2.2 持续学习流程

```
项目交付完成
    ↓
┌─────────────────────────────────────┐
│  1. 收集交付数据                           │
│  - 实际节拍时间                            │
│  - 实际清洁度达成                          │
│  - 客户反馈                                │
│  - 遇到的问题和优化措施                    │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  2. 学习记录存储                           │
│  - 存入 solutionLearningRecords 表         │
│  - 关联方案ID和项目号                      │
│  - 提取关键发现                            │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  3. 方案评分更新                           │
│  - 分析客户反馈评分                        │
│  - 更新方案成功率                          │
│  - 累积经验教训                            │
└─────────────────────────────────────┘
```

## 四、API接口清单

### 4.1 方案助手API

| 接口 | 方法 | 描述 |
|------|------|------|
| `solution.recommend` | mutation | 根据工艺参数推荐方案 |
| `solution.parse` | mutation | 解析自然语言工艺参数 |
| `solution.learn` | mutation | 从项目交付中学习 |
| `solution.create` | mutation | 创建新方案 |
| `solution.getById` | query | 获取方案详情 |
| `solution.list` | query | 获取方案列表 |
| `solution.feedback` | mutation | 提交推荐反馈 |

### 4.2 报价助手API

| 接口 | 方法 | 描述 |
|------|------|------|
| `quotation.generate` | mutation | 生成报价方案 |
| `quotation.create` | mutation | 创建报价记录 |
| `quotation.getById` | query | 获取报价详情 |
| `quotation.list` | query | 获取报价列表 |
| `quotation.analyze` | mutation | 分析报价竞争力 |

## 五、数据库表结构

### 5.1 核心表

| 表名 | 用途 | 关键字段 |
|------|------|----------|
| `historical_solutions` | 历史方案库 | solutionId, sourceType, workpieceCategory, cleanlinessStandard, cycleTime, successRate |
| `solution_recommendations` | 推荐记录 | recommendationId, userId, inputParams, recommendations, selectedSolutionId |
| `solution_learning_records` | 学习记录 | learningId, solutionId, projectNo, learningType, keyFindings |
| `historical_quotations` | 历史报价 | quotationId, customerName, customerType, equipmentModel, totalPrice, bidResult |
| `process_templates` | 工艺模板 | templateId, workpieceCategory, processSteps, standardCycleTime |

## 七、技术规范建议

### 7.1 Claude Code实现规范

为便于Claude Code在NocoBase架构中实现AI方案助理功能，建议遵循以下规范：

1. **API设计规范**
   - 使用RESTful风格或GraphQL
   - 统一错误处理格式
   - 支持分页和过滤

2. **数据模型规范**
   - 使用TypeScript类型定义
   - 遵循NocoBase数据模型约定
   - 支持多租户隔离

3. **LLM调用规范**
   - 统一使用invokeLLM函数
   - 实现请求限流
   - 记录调用日志

4. **测试规范**
   - 每个功能模块配套单元测试
   - 覆盖正常和异常场景
   - 使用vitest框架
