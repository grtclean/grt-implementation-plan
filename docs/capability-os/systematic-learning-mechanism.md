## 1. 核心原则

### 1.1 问题只允许发生一次

> **同一个问题，在组织内只允许发生一次。第二次发生，是系统的失败，不是个人的失败。**

这一原则的核心含义是：当一个问题发生时，组织的责任不仅是解决这个问题，更是确保这个问题永远不会再次发生。如果同样的问题第二次发生，说明组织的学习机制失效了。

### 1.2 为什么传统方式失效

| 传统方式 | 问题 | 后果 |
|----------|------|------|
| **口头传达** | 信息衰减，遗忘 | 新人不知道，老人忘记 |
| **邮件通知** | 淹没在信息海洋 | 没人看，没人记 |
| **培训宣贯** | 一次性，无跟踪 | 培训完就忘 |
| **制度文件** | 束之高阁 | 没人执行 |

### 1.3 系统性学习的本质

系统性学习的本质是：**将问题转化为能力，将能力固化到系统**。

```
问题 → 根因 → 措施 → 固化 → 能力
```

### 2.2 P1: 问题识别

**目标**：快速、准确地识别和记录问题

| 信息项 | 说明 | 必填 |
|--------|------|------|
| 问题描述 | 发生了什么 | 是 |
| 发生时间 | 何时发生 | 是 |
| 发生地点 | 在哪里发生 | 是 |
| 相关人员 | 谁发现、谁相关 | 是 |
| 影响范围 | 造成什么影响 | 是 |
| 紧急程度 | 是否需要立即处理 | 是 |
| 初步原因 | 初步判断的原因 | 否 |

**问题分类**：

| 类别 | 说明 | 示例 |
|------|------|------|
| **技术问题** | 技术方案或实现的问题 | 设备故障、软件Bug |
| **流程问题** | 流程设计或执行的问题 | 漏检、错发 |
| **能力问题** | 人员能力不足的问题 | 操作失误、判断错误 |
| **资源问题** | 资源不足或配置不当 | 工具缺失、人手不够 |
| **沟通问题** | 信息传递或理解的问题 | 需求误解、信息遗漏 |

**问题分级**：

| 级别 | 定义 | 响应时间 | 闭环时间 |
|------|------|----------|----------|
| **P0-紧急** | 影响客户生产，需立即处理 | 1小时 | 24小时 |
| **P1-严重** | 影响交付质量，需优先处理 | 4小时 | 72小时 |
| **P2-一般** | 影响效率，需计划处理 | 24小时 | 7天 |
| **P3-轻微** | 影响较小，可安排处理 | 72小时 | 14天 |

### 2.3 P2: 根因分析

**目标**：找到问题的根本原因，而非表面原因

**5Why分析法**：

| 层级 | 问题 | 示例 |
|------|------|------|
| Why 1 | 为什么发生这个问题？ | 设备调试失败 |
| Why 2 | 为什么调试失败？ | 参数设置错误 |
| Why 3 | 为什么参数设置错误？ | 工程师不熟悉该型号 |
| Why 4 | 为什么工程师不熟悉？ | 没有接受过该型号培训 |
| Why 5 | 为什么没有培训？ | 培训计划没有覆盖新型号 |
| **根因** | 培训计划更新机制缺失 | |

**根因分类**：

| 根因类型 | 说明 | 典型表现 |
|----------|------|----------|
| **知识缺失** | 不知道应该怎么做 | 没培训、没文档 |
| **技能不足** | 知道但做不到 | 需要更多练习 |
| **流程缺陷** | 流程设计有漏洞 | 检查点缺失 |
| **资源不足** | 缺少必要资源 | 工具、时间、人力 |
| **沟通失效** | 信息没有传递到位 | 接口不清晰 |

### 2.4 P3: 措施制定

**目标**：制定有效的纠正措施和预防措施

| 措施类型 | 说明 | 时效 |
|----------|------|------|
| **临时措施** | 快速止血，防止影响扩大 | 立即 |
| **纠正措施** | 解决当前问题 | 短期 |
| **预防措施** | 防止问题再次发生 | 长期 |

**措施制定原则**：

| 原则 | 说明 |
|------|------|
| **针对根因** | 措施必须针对根因，而非表面原因 |
| **可执行** | 措施必须具体、可操作 |
| **可验证** | 措施效果必须可以验证 |
| **有责任人** | 每条措施必须有明确责任人 |
| **有时间节点** | 每条措施必须有完成时间 |

### 2.5 P4: 固化验证

**目标**：确保措施被固化到系统中，并验证效果

**固化层级**：

| 层级 | 固化方式 | 强制程度 | 示例 |
|------|----------|----------|------|
| **L1-知识** | 知识库文档 | 可查询 | 问题案例入库 |
| **L2-清单** | 检查清单 | 提醒执行 | FAT清单增加检查项 |
| **L3-培训** | 培训课程 | 考核通过 | 培训内容更新 |
| **L4-流程** | 流程节点 | 强制执行 | 审批流程增加节点 |
| **L5-系统** | 系统约束 | 无法绕过 | 系统自动校验 |

**效果验证**：

| 验证方式 | 说明 | 周期 |
|----------|------|------|
| **措施执行验证** | 措施是否按计划执行 | 按措施时间节点 |
| **效果验证** | 问题是否不再发生 | 措施完成后1-3个月 |
| **复盘验证** | 同类问题是否再次发生 | 季度/年度 |
