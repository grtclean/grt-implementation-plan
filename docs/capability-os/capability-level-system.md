## 1. 核心理念

### 1.1 能力为核心，而非岗位

> **GRT的核心不是岗位，而是能力。岗位是能力的组合表达，能力是组织的真正资产。**

传统组织以岗位为中心，存在三个根本问题：

| 问题 | 表现 | 后果 |
|------|------|------|
| **岗位固化** | 人被绑定在岗位上，能力无法流动 | 组织僵化，人才浪费 |
| **评估主观** | 依赖主管打分，标准因人而异 | 员工不服气，评估缺乏公信力 |
| **能力不可见** | 能力藏在岗位背后，无法量化 | 无法精准匹配任务与人员 |

GRT能力操作系统的核心设计原则是：**能力是一级主数据，能力等级完全由系统计算，基于客观证据，实时更新，可追溯验证。**

### 1.2 能力来源于证据，而非培训或评价

> **能力来源不是培训或评价，而是来自真实的项目、服务与结果证据。**

| 传统方式 | GRT方式 |
|----------|---------|
| 参加培训 → 获得证书 → 认定能力 | 完成项目 → 产生证据 → 系统计算能力 |
| 主管评价 → 打分 → 定级 | 客户验收 → 问题解决 → 自动升级 |
| 年度评估 → 周期长 | 实时计算 → 即时反映 |

### 1.3 系统自动触发升级，不允许人工主观升级

> **能力升级必须由系统证据自动触发，不允许人工主观升级。**

这是GRT能力体系的铁律。任何能力等级的变化，必须：
1. 有明确的证据支撑
2. 由系统自动计算触发
3. 可追溯、可验证
4. 不受人为干预

## 4. 能力证据体系

### 4.1 证据来源

能力证据必须来自真实的项目、服务与结果，不接受培训或主观评价作为证据。

| 证据来源 | 说明 | 采集方式 | 可信度 |
|----------|------|----------|--------|
| **项目交付** | 项目各阶段的交付记录 | 系统自动采集 | 高 |
| **服务工单** | 现场服务的完成记录 | 系统自动采集 | 高 |
| **客户验收** | 客户签字确认的验收记录 | 客户签字 | 最高 |
| **问题解决** | 故障诊断和解决的记录 | 系统自动采集 | 高 |
| **知识贡献** | 知识文档、培训课程的提交 | 系统自动采集 | 中 |
| **同行评审** | 专家或同事的评审记录 | 评审系统 | 中 |

### 4.2 证据质量评分

每条证据都有质量评分，影响最终积分计算。

| 质量维度 | 评分标准 | 权重 |
|----------|----------|------|
| **任务复杂度** | 简单(1分) / 标准(2分) / 复杂(3分) / 疑难(4分) / 创新(5分) | 40% |
| **客户等级** | 普通(1分) / 重要(2分) / 战略(3分) / Tier1(4分) | 30% |
| **独立程度** | 协助(1分) / 指导下(2分) / 独立(3分) / 主导(4分) | 30% |

**证据质量分 = Σ(维度评分 × 维度权重)**

### 4.3 证据时效衰减

证据的有效性随时间衰减，确保能力等级反映当前状态。

| 时间范围 | 衰减系数 | 说明 |

### 5.1 计算公式

```
能力等级 = f(证据积分, 证据质量, 证据时效, 能力衰减)

单条证据积分 = 基础分 × 质量系数 × 时效系数

能力总积分 = Σ(单条证据积分)
```
