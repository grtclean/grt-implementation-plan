## 一、核心理念

### 1.1 证据驱动的能力管理

GRT能力操作系统的核心原则是：**能力来源于证据，而非培训或评价**。

这意味着：
- **不接受主观评价**：主管的"我认为他能力不错"不能作为能力证据
- **不接受培训记录**：参加培训≠具备能力，培训只是学习机会
- **只接受结果证据**：真实项目、服务、交付中产生的可验证结果

### 1.2 证据的三个特征

| 特征 | 定义 | 示例 |
|------|------|------|
| **可验证** | 证据必须可以被第三方独立验证 | 服务报告有客户签字确认 |
| **可量化** | 证据必须能够转化为数值 | 故障解决时间、客户满意度评分 |
| **可追溯** | 证据必须关联到具体的项目/服务/时间 | 2026年1月ZF项目M3阶段交付 |

### 3.3 证据验证规则

每条证据在计入积分前，必须通过以下验证：

1. **完整性验证**：证据必须包含时间、项目、结果等必填字段
2. **真实性验证**：证据必须有系统记录或第三方确认
3. **时效性验证**：证据必须在有效期内（默认2年）
4. **去重验证**：同一事件不能重复计分

## 四、能力积分计算公式

### 4.1 单项能力积分

```
能力域积分 = Σ(证据权重 × 证据数量 × 时效系数)

时效系数：
- 1年内：1.0
- 1-2年：0.8
- 2-3年：0.5
- 3年以上：0.3
```

### 4.2 综合能力评估

```
综合能力指数 = (T×0.25 + S×0.15 + D×0.25 + C×0.15 + K×0.10 + L×0.10) / 100

其中：
- T、S、D、C、K、L 为各能力域的等级分数（L1=1, L2=2, L3=3, L4=4, L5=5）
- 权重根据岗位类型可调整
```

### 4.3 能力等级自动升级

```
升级条件：
1. 目标等级积分达标
2. 无重大质量事故（近6个月）
3. 无客户投诉（近3个月）

升级流程：
系统检测积分达标 → 自动验证条件 → 自动升级等级 → 通知工程师和主管
```

## 六、系统集成要求

### 6.1 NocoBase数据模型

```sql
-- 能力证据表
CREATE TABLE capability_evidence (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    engineer_id BIGINT NOT NULL,
    capability_domain ENUM('T', 'S', 'D', 'C', 'K', 'L') NOT NULL,
    evidence_type VARCHAR(50) NOT NULL,
    evidence_source VARCHAR(100) NOT NULL,
    source_id VARCHAR(100) NOT NULL,
    score INT NOT NULL,
    collected_at DATETIME NOT NULL,
    verified_at DATETIME,
    verified_by BIGINT,
    expires_at DATETIME,
    status ENUM('pending', 'verified', 'rejected', 'expired') DEFAULT 'pending',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 能力积分表
CREATE TABLE capability_scores (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    engineer_id BIGINT NOT NULL,
    capability_domain ENUM('T', 'S', 'D', 'C', 'K', 'L') NOT NULL,
    total_score INT DEFAULT 0,
    current_level ENUM('L1', 'L2', 'L3', 'L4', 'L5') DEFAULT 'L1',
    last_calculated_at DATETIME,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY (engineer_id, capability_domain)
);

-- 能力升级记录表
CREATE TABLE capability_upgrades (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    engineer_id BIGINT NOT NULL,
    capability_domain ENUM('T', 'S', 'D', 'C', 'K', 'L') NOT NULL,
    from_level ENUM('L1', 'L2', 'L3', 'L4', 'L5') NOT NULL,
    to_level ENUM('L1', 'L2', 'L3', 'L4', 'L5') NOT NULL,
    trigger_type ENUM('auto', 'manual') DEFAULT 'auto',
    evidence_ids JSON,
    upgraded_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```
