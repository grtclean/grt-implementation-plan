### 1.2 域划分原则

| 原则 | 说明 | 目的 |
|------|------|------|
| **能力为核心** | 能力管理域是一级核心域 | 所有业务围绕能力展开 |
| **场景为载体** | 业务域是能力训练验证场景 | 业务产生能力证据 |
| **数据互通** | 域之间数据互通 | 支持能力计算和分析 |
| **边界清晰** | 每个域职责明确 | 避免职责重叠 |

## 2. 能力管理域（核心域）

### 2.1 域定位

> **能力管理域是GRT能力操作系统的核心，是一级主数据的管理中心。所有其他域都是能力的训练场和验证场。**

### 2.2 为什么能力是核心

| 传统模式 | 能力核心模式 |
|----------|--------------|
| 项目是核心，人是资源 | 能力是核心，项目是训练场 |
| 关注项目交付结果 | 关注能力积累和复用 |
| 人员调配靠经验 | 人员调配靠能力匹配 |
| 问题解决靠个人 | 问题解决靠组织能力 |

### 2.3 模块组成

| 模块 | 职责 | 核心功能 |
|------|------|----------|
| **能力定义管理** | 定义和维护能力体系 | 能力目录、能力标准、能力关系 |
| **能力评估引擎** | 计算和评估能力等级 | L1-L5计算、能力画像、能力对比 |
| **能力证据库** | 存储和管理能力证据 | 证据采集、证据验证、证据关联 |
| **能力发展路径** | 规划能力提升路径 | 学习路径、培训推荐、能力预测 |

### 2.4 核心数据模型

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| **Capability** | 能力定义 | 能力ID、名称、类型、等级标准 |
| **CapabilityLevel** | 能力等级 | L1-L5定义、晋升条件 |
| **Evidence** | 能力证据 | 证据类型、来源、权重、有效期 |
| **PersonCapability** | 人员能力 | 人员ID、能力ID、当前等级、证据列表 |

### 2.5 与其他域的关系

| 关系 | 说明 |
|------|------|
| **→ 现场服务域** | 提供能力匹配，接收服务证据 |
| **→ 项目交付域** | 提供能力门槛，接收项目证据 |
| **→ 制造调试域** | 提供能力认证，接收调试证据 |
| **→ 客户智能域** | 提供能力推荐，接收客户反馈 |
| **→ 知识学习域** | 提供能力差距，接收学习证据 |

## 3. 现场服务能力域

### 3.1 域定位

> **现场服务能力域是能力的主要验证场，每一次现场服务都是能力的实战检验。**

### 3.2 为什么这样设计

| 问题 | 解决方案 |
|------|----------|
| 服务质量依赖个人 | 能力匹配确保派遣合适的人 |
| 服务过程不可见 | 服务记录产生能力证据 |
| 服务经验不沉淀 | 服务案例转化为知识 |
| 服务能力难评估 | 服务结果反馈能力评估 |

### 3.3 模块组成

| 模块 | 职责 | 核心功能 |
|------|------|----------|
| **服务派遣** | 基于能力匹配派遣 | 能力匹配、资源调度、派遣优化 |
| **现场执行** | 支持现场服务执行 | 任务指引、检查清单、实时记录 |
| **问题解决** | 支持现场问题处理 | 知识推荐、专家支持、问题上报 |
| **服务报告** | 生成和管理服务报告 | 报告生成、客户确认、证据采集 |

### 3.4 能力证据采集

| 证据类型 | 来源 | 权重 |
|----------|------|------|
| 服务任务完成 | 服务工单 | 标准 |
| 客户评价 | 客户反馈 | 高 |
| 问题解决 | 问题工单 | 高 |
| 首次解决率 | 服务统计 | 中 |
| 服务时效 | 服务记录 | 中 |

### 3.5 能力门槛约束

| 服务类型 | 能力要求 | 系统约束 |
|----------|----------|----------|
| 常规维护 | L2+ | 派遣系统校验 |
| 故障维修 | L3+ | 派遣系统校验 |
| 复杂调试 | L4+ | 派遣系统校验 |
| Tier1服务 | L4+，需认证 | 派遣系统校验+认证校验 |

## 4. 项目交付能力域

### 4.1 域定位

> **项目交付能力域是能力的高强度训练场，特别是Tier1项目，是组织能力的最高验证标准。**

### 4.2 为什么这样设计

| 问题 | 解决方案 |
|------|----------|
| 项目质量不稳定 | Gate管控确保质量 |
| Tier1风险高 | 红蓝对抗前置发现问题 |
| 项目经验不传承 | 项目复盘沉淀知识 |
| 团队能力不匹配 | 能力门槛确保团队配置 |

### 4.3 模块组成

| 模块 | 职责 | 核心功能 |
|------|------|----------|
| **项目管理** | 项目全生命周期管理 | 项目立项、进度管理、资源管理 |
| **Gate管控** | M0-M12阶段门禁 | Gate定义、Gate评审、Gate决策 |
| **红蓝对抗** | Tier1项目质量保障 | 蓝队组建、对抗审查、问题闭环 |
| **交付验收** | 项目交付和验收 | FAT/SAT、客户验收、项目收尾 |

### 4.4 Gate管控体系

| Gate | 阶段 | 关键检查点 |
|------|------|------------|
| M0 | 商机确认 | 需求可行性、能力匹配度 |
| M2 | 方案设计 | 技术方案、风险评估 |
| M4 | 设计评审 | 详细设计、资源计划 |
| M6 | 生产准备 | 物料齐套、生产计划 |
| M8 | FAT验收 | 工厂测试、质量确认 |
| M10 | SAT验收 | 现场安装、性能验证 |
| M12 | 项目收尾 | 客户验收、项目总结 |

### 4.5 能力证据采集

| 证据类型 | 来源 | 权重 |
|----------|------|------|
| 项目角色承担 | 项目记录 | 按角色权重 |
| Gate通过 | Gate评审 | 中 |
| 红蓝对抗参与 | 对抗记录 | 高 |
| 项目成功交付 | 验收记录 | 高（Tier1加成） |
| 项目复盘贡献 | 复盘记录 | 中 |

## 5. 制造调试能力域

### 5.1 域定位

> **制造调试能力域是能力的专业训练场，是技术能力的核心积累区域。**

### 5.2 为什么这样设计

| 问题 | 解决方案 |
|------|----------|
| 调试质量依赖个人 | 能力认证确保资质 |
| 调试经验难传承 | 调试记录沉淀知识 |
| 质量问题后置 | FAT前置发现问题 |
| 新人上手慢 | 能力路径指导成长 |

### 5.3 模块组成

| 模块 | 职责 | 核心功能 |
|------|------|----------|
| **生产制造** | 生产过程管理 | 生产计划、工序管理、质量控制 |
| **设备调试** | 设备调试管理 | 调试任务、调试记录、参数管理 |
| **FAT/SAT** | 验收测试管理 | 测试计划、测试执行、测试报告 |
| **质量检测** | 质量检测管理 | 检测标准、检测记录、不合格处理 |

### 5.4 能力认证体系

| 认证类型 | 要求 | 有效期 |
|----------|------|--------|
| 超声波调试认证 | L3+，理论+实操考核 | 2年 |
| 真空系统调试认证 | L3+，理论+实操考核 | 2年 |
| PLC编程认证 | L3+，理论+项目考核 | 2年 |
| 高级调试认证 | L4+，复杂项目验证 | 2年 |

### 5.5 能力证据采集

| 证据类型 | 来源 | 权重 |
|----------|------|------|
| 调试任务完成 | 调试记录 | 标准 |
| FAT一次通过 | FAT记录 | 高 |
| 质量问题解决 | 质量记录 | 高 |
| 调试效率 | 工时统计 | 中 |
| 认证获取 | 认证记录 | 高 |

## 6. 客户智能服务域

### 6.1 域定位

> **客户智能服务域是能力价值的最终体现，通过为客户提供智能化服务，验证和展示组织能力。**

### 6.2 为什么这样设计

| 问题 | 解决方案 |
|------|----------|
| 客户服务标准不一 | 客户分级差异化服务 |
| 服务协议难执行 | 系统约束服务标准 |
| 客户需求难预测 | 智能推荐主动服务 |
| 服务价值难体现 | 同核裁剪展示能力 |

### 6.3 模块组成

| 模块 | 职责 | 核心功能 |
|------|------|----------|
| **客户分级** | 客户等级管理 | Tier1/2/3分级、等级评估、等级调整 |
| **服务协议** | 服务协议管理 | SLA定义、SLA监控、SLA报告 |
| **同核裁剪** | 客户版系统裁剪 | 功能裁剪、数据隔离、权限控制 |
| **智能推荐** | 智能服务推荐 | 预防性维护、备件推荐、升级建议 |

### 6.4 客户分级标准

| 等级 | 定义 | 服务标准 |
|------|------|----------|
| **Tier1** | 战略客户 | 专属团队、红蓝对抗、最高优先级 |
| **Tier2** | 重要客户 | 优先响应、定期回访、专业支持 |
| **Tier3** | 普通客户 | 标准服务、常规支持 |

### 6.5 同核裁剪版

> **同核裁剪版是为Tier1客户提供的定制化系统，与GRT内部系统共享核心能力，但进行功能裁剪和数据隔离。**

| 裁剪维度 | 说明 |
|----------|------|
| **功能裁剪** | 只开放客户相关功能 |
| **数据隔离** | 只展示客户自己的数据 |
| **权限控制** | 客户只能操作授权功能 |
| **界面定制** | 客户品牌和界面定制 |

## 9. 技术实现架构

| 平台 | 角色 | 职责 |
|------|------|------|
| **NocoBase** | 核心业务平台 | 主数据管理、业务流程、数据存储 |

| **AI引擎** | 建议与分析 | 智能推荐、数据分析、辅助决策 |

### 9.2 NocoBase作为核心平台

> **NocoBase是GRT能力操作系统的核心业务平台，承载所有主数据和业务流程。**

| 职责 | 说明 |
|------|------|
| **主数据管理** | 能力、人员、客户、项目等主数据 |
| **业务流程** | 服务派遣、项目管理、审批流程等 |
| **数据存储** | 所有业务数据的持久化存储 |
| **权限控制** | 基于角色和能力的权限控制 |

### 9.3 Manus作为规划与表达层

> **Manus是GRT能力操作系统的规划、蓝图与对内/对外表达层。**

| 职责 | 说明 |
|------|------|
| **系统规划** | 系统架构设计、功能规划 |
| **蓝图维护** | 系统蓝图的更新和维护 |
| **对内表达** | 公司内部的系统说明和培训 |
| **对外表达** | Tier1客户沟通、系统展示 |

### 9.4 AI作为建议与分析引擎

> **AI仅作为建议与分析引擎，不具备决策权。所有AI输出必须经过人工确认。**

| AI功能 | 说明 | 人工确认 |
|--------|------|----------|
| 能力评估建议 | AI计算能力等级 | 需人工审核 |
| 派遣推荐 | AI推荐派遣人选 | 需人工确认 |
| 问题分析 | AI辅助根因分析 | 需人工验证 |
| 知识推荐 | AI推荐相关知识 | 参考使用 |
| 风险预警 | AI识别潜在风险 | 需人工评估 |
