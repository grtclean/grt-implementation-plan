> **版本**: 1.0  
> **生效日期**: 2026年1月17日  
> **适用范围**: 设备型号命名规则、项目编号规则、物料编号规则  
> **作者**: Manus AI  
> **状态**: 正式发布

---

## 一、变更管理概述

### 1.1 目的

本文档规范GRT公司命名规则（设备型号、项目编号、物料编号）的变更管理流程，确保：

1. **可追溯性**：所有变更有完整的审批和实施记录
2. **一致性**：变更按统一流程执行，避免混乱
3. **可控性**：变更经过充分测试后才能发布正式版本
4. **版本化**：每次变更生成新版本，历史版本可追溯

### 1.2 适用范围

| 规则类型 | 基础数据表文档 | 说明 |
|----------|----------------|------|
| 设备型号命名规则 | equipment-model-master-data.md | 设备大类、功能名称、数字代码等 |
| 项目编号规则 | project-numbering-master-data.md | T编号、GRT编号、文档编号等 |
| 物料编号规则 | material-numbering-rules.md | 物料大类、中类、规格代码等 |

## 二、变更管理流程

### 2.1 流程概览

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  1. 提出    │───▶│  2. 批准    │───▶│  3. Claude  │───▶│  4. 测试    │───▶│  5. 更新    │───▶│  6. 正式    │
│     要求    │    │             │    │  Code更新   │    │  系统实施   │    │     记录    │    │     版本    │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
      │                  │                  │                  │                  │                  │
      ▼                  ▼                  ▼                  ▼                  ▼                  ▼
   变更请求           审批记录          开发环境           测试环境           变更历史           正式发布
   (CR单)            (批准/驳回)        (代码更新)         (验证测试)         (记录归档)         (版本号)
```

### 2.2 详细流程说明

#### 阶段1：提出要求

**触发条件**：
- 新增设备型号/项目类型/物料类别
- 修改现有命名规则
- 修正命名错误
- 业务流程变更导致的规则调整

**执行步骤**：
1. 填写《命名规则变更请求单》（见附录A）
2. 明确变更内容、原因、影响范围
3. 提交给规则管理员

**输出物**：
- 变更请求单（CR-YYYYMMDD-XXX）

---

#### 阶段2：批准

**审批角色**：

| 变更类型 | 审批人 | 说明 |
|----------|--------|------|
| 新增型号/编号 | 研发经理 | 新增设备型号、物料类别等 |
| 修改规则结构 | 技术总监 | 编码结构、命名体系变更 |
| 修正错误 | 规则管理员 | 文字错误、数据修正 |
| 重大变更 | 总经理 | 影响全公司的规则变更 |

**执行步骤**：
1. 审批人评估变更影响
2. 确认变更必要性和合理性
3. 批准或驳回（附说明）

**输出物**：
- 审批记录（批准/驳回 + 审批意见）

---

#### 阶段3：Claude Code更新

**执行角色**：Manus AI / Claude Code

**执行步骤**：
1. 根据批准的变更请求，更新相关文档
2. 更新数据库Schema（如需要）
3. 更新系统代码（如需要）
4. 生成变更差异报告

**输出物**：
- 更新后的文档（草稿版本）
- 代码变更记录
- 差异报告

**版本标记**：
- 草稿版本使用后缀 `-draft`，如 `V1.1-draft`

---

#### 阶段4：测试系统实施

**执行角色**：测试人员 / 业务人员

**执行步骤**：
1. 在测试环境部署变更
2. 验证新规则的正确性
3. 验证与现有数据的兼容性
4. 执行回归测试
5. 记录测试结果

**测试检查清单**：

| 检查项 | 说明 | 通过标准 |
|--------|------|----------|
| 格式校验 | 新编码格式是否正确 | 符合规则定义 |
| 唯一性校验 | 新编码是否与现有编码冲突 | 无重复 |
| 兼容性校验 | 现有数据是否受影响 | 现有数据正常显示 |
| 功能校验 | 系统功能是否正常 | 所有功能可用 |
| 版本校验 | 版本号是否正确关联 | 版本号正确 |

**输出物**：
- 测试报告（通过/不通过 + 问题清单）

---

#### 阶段5：更新记录

**执行角色**：规则管理员

**执行步骤**：
1. 确认测试通过
2. 更新变更历史表
3. 记录变更详情（变更内容、生效日期、版本号）
4. 归档相关文档

**变更历史记录格式**：

| 字段 | 说明 |
|------|------|
| 变更编号 | CR-YYYYMMDD-XXX |
| 变更类型 | 新增/修改/删除/修正 |
| 变更内容 | 具体变更描述 |
| 影响范围 | 受影响的规则/数据 |
| 旧版本 | 变更前版本号 |
| 新版本 | 变更后版本号 |
| 生效日期 | 新规则生效日期 |
| 审批人 | 审批人姓名 |
| 执行人 | 执行人姓名 |
| 测试人 | 测试人姓名 |
| 备注 | 其他说明 |

**输出物**：
- 变更历史记录
- 归档文档

---

#### 阶段6：生成正式版本

**执行角色**：规则管理员 / Manus AI

**执行步骤**：
1. 移除草稿标记，生成正式版本号
2. 更新基础数据表文档的版本信息
3. 更新版本历史表
4. 通知相关人员
5. 在生产环境发布（如需要）

**版本号规则**：

| 变更类型 | 版本号变化 | 示例 |
|----------|------------|------|
| 重大变更（结构调整） | 主版本+1 | V1.0 → V2.0 |
| 次要变更（新增/修改） | 次版本+1 | V1.0 → V1.1 |
| 修正（勘误） | 修订版+1 | V1.0 → V1.0.1 |

**输出物**：
- 正式版本文档
- 版本发布通知

## 三、变更记录表

### 3.1 变更请求记录表 (naming_change_requests)

| 字段名 | 数据类型 | 说明 |
|--------|----------|------|
| id | INT | 主键 |
| request_code | VARCHAR(20) | 变更请求编号，如CR-20260117-001 |
| request_type | ENUM | 变更类型：add(新增), modify(修改), delete(删除), correct(修正) |
| rule_type | ENUM | 规则类型：equipment(设备), project(项目), material(物料) |
| title | VARCHAR(200) | 变更标题 |
| description | TEXT | 变更详细描述 |
| reason | TEXT | 变更原因 |
| impact_scope | TEXT | 影响范围 |
| requestor_id | INT | 申请人ID |
| requestor_name | VARCHAR(100) | 申请人姓名 |
| request_date | DATE | 申请日期 |
| status | ENUM | 状态：pending(待审批), approved(已批准), rejected(已驳回), implementing(实施中), testing(测试中), completed(已完成), cancelled(已取消) |
| approver_id | INT | 审批人ID |
| approver_name | VARCHAR(100) | 审批人姓名 |
| approval_date | DATE | 审批日期 |
| approval_notes | TEXT | 审批意见 |
| old_version | VARCHAR(10) | 变更前版本 |
| new_version | VARCHAR(10) | 变更后版本 |
| effective_date | DATE | 生效日期 |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

### 3.2 变更实施记录表 (naming_change_implementations)

| 字段名 | 数据类型 | 说明 |
|--------|----------|------|
| id | INT | 主键 |
| request_id | INT | 关联变更请求ID |
| phase | ENUM | 实施阶段：development(开发), testing(测试), recording(记录), release(发布) |
| executor_id | INT | 执行人ID |
| executor_name | VARCHAR(100) | 执行人姓名 |
| start_time | TIMESTAMP | 开始时间 |
| end_time | TIMESTAMP | 结束时间 |
| status | ENUM | 状态：in_progress(进行中), completed(已完成), failed(失败) |
| result | TEXT | 执行结果 |
| notes | TEXT | 备注 |
| attachments | TEXT | 附件（JSON格式，存储文件路径） |
| created_at | TIMESTAMP | 创建时间 |

### 3.3 测试记录表 (naming_change_tests)

| 字段名 | 数据类型 | 说明 |
|--------|----------|------|
| id | INT | 主键 |
| request_id | INT | 关联变更请求ID |
| tester_id | INT | 测试人ID |
| tester_name | VARCHAR(100) | 测试人姓名 |
| test_date | DATE | 测试日期 |
| test_environment | VARCHAR(50) | 测试环境 |
| test_items | TEXT | 测试项目（JSON格式） |
| test_result | ENUM | 测试结果：pass(通过), fail(不通过), partial(部分通过) |
| issues | TEXT | 问题清单（JSON格式） |
| notes | TEXT | 备注 |
| created_at | TIMESTAMP | 创建时间 |

## 四、角色与职责

### 4.1 角色定义

| 角色 | 职责 | 权限 |
|------|------|------|
| **申请人** | 提出变更请求，说明变更原因和内容 | 创建变更请求 |
| **审批人** | 评估变更影响，批准或驳回请求 | 审批变更请求 |
| **规则管理员** | 管理命名规则，协调变更流程 | 管理变更流程、更新记录 |
| **开发人员** | 实施变更，更新代码和文档 | 更新系统和文档 |
| **测试人员** | 验证变更，执行测试 | 执行测试、记录结果 |
| **Manus AI** | 辅助规划和文档更新 | 生成文档、提供建议 |
| **Claude Code** | 执行代码更新和系统实施 | 更新代码、执行部署 |

### 4.2 协作流程

```
申请人 ──提交请求──▶ 规则管理员 ──分配审批──▶ 审批人
                                                │
                                           批准/驳回
                                                │
                                                ▼
Claude Code ◀──分配实施── 规则管理员 ◀──批准通知──┘
    │
    │ 开发完成
    ▼
测试人员 ──测试报告──▶ 规则管理员 ──确认发布──▶ 正式版本
```
