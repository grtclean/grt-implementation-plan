                              ↓ 任务规格文档

│                     【实现层】Claude Code                                │
│  ┌─────────────────────────────────────────────────────────────────┐    │

## 2. 角色职责定义

### 2.1 Manus - 规划与管理

Manus作为项目的"项目经理"和"架构师"，负责整体规划和质量把控。

| 职责领域 | 具体任务 | 输出物 |
|----------|----------|--------|
| **需求分析** | 理解用户需求，转化为技术规格 | 需求文档、技术规格书 |
| **任务拆解** | 将大功能拆分为可执行的小任务 | 任务清单、todo.md |
| **架构设计** | 设计系统架构和数据模型 | 架构图、Schema设计 |
| **进度跟踪** | 监控开发进度，更新任务状态 | 进度报告 |
| **质量检查** | 审查代码实现，确保符合规范 | 代码审查报告 |
| **文档维护** | 生成和维护项目文档 | 部署指南、API文档 |
| **版本发布** | 管理版本发布和checkpoint | 发布说明 |

### 2.2 Claude Code - 代码实现

Claude Code作为项目的"开发工程师"，负责具体的代码实现工作。

| 职责领域 | 具体任务 | 输出物 |
|----------|----------|--------|
| **Schema设计** | 实现数据库表结构 | drizzle/schema.ts |
| **API开发** | 实现tRPC后端接口 | server/*.ts |
| **前端开发** | 实现React页面和组件 | client/src/pages/*.tsx |
| **测试编写** | 编写单元测试 | *.test.ts |
| **Bug修复** | 定位和修复代码问题 | 修复代码 |
| **代码重构** | 优化代码结构 | 重构代码 |

### 2.3 ChatGPT - 迭代优化

ChatGPT作为项目的"技术顾问"，负责代码审查和优化建议。

| 职责领域 | 具体任务 | 输出物 |
|----------|----------|--------|
| **代码审查** | 审查代码质量和安全性 | 审查报告 |
| **性能优化** | 分析和优化性能瓶颈 | 优化方案 |
| **UX改进** | 提升用户体验 | 改进建议 |
| **问题诊断** | 排查复杂问题 | 诊断报告 |
| **最佳实践** | 指导遵循最佳实践 | 实践指南 |

## 3. Manus规划层工作流程

### 3.1 需求分析流程

当用户提出新需求时，Manus执行以下流程：

**步骤1：需求理解**

与用户沟通，明确需求的业务背景、目标用户、核心功能和约束条件。

**步骤2：可行性分析**

评估技术可行性，识别潜在风险和依赖关系。

**步骤3：生成任务规格文档**

在 `docs/dev-specs/` 目录创建详细的任务规格文档：

```markdown
# 任务名称

## 1. 需求背景
[描述业务需求和目标]

## 2. 技术规格

### 2.1 数据库Schema
```typescript
// 表结构定义
export const tableName = mysqlTable("table_name", {
  id: int().autoincrement().notNull(),
  // ... 字段定义
});
```

### 2.2 API接口
```typescript
// tRPC接口定义
router.procedureName = protectedProcedure
  .input(z.object({ /* 输入参数 */ }))
  .mutation(async ({ ctx, input }) => {
    // 实现逻辑
  });
```

### 2.3 前端页面
- 页面路由：/path/to/page
- 组件结构：[组件层次描述]
- 交互逻辑：[用户交互描述]

## 3. 实现步骤
1. [ ] 步骤1：创建数据库Schema
2. [ ] 步骤2：实现API接口
3. [ ] 步骤3：创建前端页面
4. [ ] 步骤4：编写单元测试

## 4. 测试要求
- 单元测试覆盖率：≥80%
- 集成测试场景：[测试场景列表]

## 5. 验收标准
- [ ] 功能正常运行
- [ ] 无控制台错误
- [ ] 响应时间<500ms
- [ ] 通过所有测试
```

**步骤4：更新任务清单**

在 `todo.md` 中添加新任务：

```markdown
## v1.3.73 新功能

- [ ] **任务名称**
    - [ ] 创建数据库Schema
    - [ ] 实现API接口
    - [ ] 创建前端页面
    - [ ] 编写单元测试
```

### 3.2 进度跟踪流程

**日常跟踪**

1. 检查todo.md中的任务状态
2. 与用户确认已完成的任务
3. 更新任务状态（[ ] → [x]）
4. 识别阻塞问题并协调解决

**里程碑检查**

1. 验证功能实现是否符合规格
2. 运行测试确保质量
3. 保存checkpoint
4. 生成进度报告

### 3.3 版本发布流程

**发布前检查**

1. 确认所有计划任务已完成
2. 确认所有测试通过
3. 确认文档已更新
4. 确认todo.md状态正确

**发布操作**

1. 保存checkpoint（webdev_save_checkpoint）
2. 生成发布说明
3. 更新CHANGELOG.md
4. 通知用户发布完成

## 4. Claude Code实现层工作流程

### 4.1 开发环境准备

**VS Code配置**

确保已安装Claude扩展并配置API密钥。

**项目上下文加载**

在开始开发前，让Claude了解项目上下文：

```
项目：GRT智能系统 v1.3.72
技术栈：React 19 + TypeScript + Tailwind CSS 4 + tRPC 11 + Drizzle ORM
数据库：MySQL 8.0
当前任务：[从Manus获取的任务规格文档]
```

### 4.2 功能开发流程

**步骤1：阅读任务规格**

```
请阅读 docs/dev-specs/v1.3.73/task-xxx.md 中的任务规格，
理解需求后开始实现。
```

**步骤2：实现数据库Schema**

```
根据任务规格，在 drizzle/schema.ts 中添加新表定义。
完成后运行 pnpm db:push 同步数据库。
```

**步骤3：实现API接口**

```
在 server/routers.ts 或新建路由文件中实现tRPC接口。
确保使用正确的procedure类型（publicProcedure/protectedProcedure）。
```

**步骤4：实现前端页面**

```
在 client/src/pages/ 中创建新页面组件。
使用shadcn/ui组件库，遵循项目样式规范。
在 client/src/App.tsx 中添加路由。
```

**步骤5：编写单元测试**

```
在 server/*.test.ts 中添加API接口测试。
运行 pnpm test 确保测试通过。
```

### 4.3 Bug修复流程

**步骤1：问题定位**

```
请分析以下错误信息，定位问题原因：
[错误信息]
相关文件：[文件路径]
```

**步骤2：修复实现**

```
根据分析结果，修复 [文件路径] 中的问题。
修复后验证功能正常。
```

**步骤3：回归测试**

```
运行相关测试确保修复没有引入新问题：

```

### 4.4 代码规范

| 规范项 | 要求 | 示例 |
|--------|------|------|
| **命名规范** | 组件PascalCase，函数camelCase | `UserProfile`, `getUserById` |
| **文件命名** | 页面PascalCase，工具kebab-case | `UserProfile.tsx`, `date-utils.ts` |
| **类型定义** | 使用TypeScript严格模式 | `interface User { id: number }` |
| **API调用** | 使用tRPC hooks | `trpc.user.getById.useQuery()` |
| **样式** | 使用Tailwind CSS | `className="flex items-center"` |
| **组件** | 使用shadcn/ui | `import { Button } from "@/components/ui/button"` |

## 6. 代码同步与版本管理

### 6.1 GitHub同步方案（推荐）

**初始设置**

1. 在Manus中导出代码到GitHub
2. 本地克隆仓库

```powershell
git clone https://github.com/your-org/grt-implementation-plan.git D:\Projects\grt-implementation-plan
cd D:\Projects\grt-implementation-plan
```

**日常同步流程**

```powershell
# 1. 拉取最新代码（从Manus同步的更新）
git pull origin main

# 2. 本地开发...

# 3. 提交本地更改
git add .
git commit -m "feat: 实现xxx功能"

# 4. 推送到GitHub
git push origin main

# 5. Manus从GitHub拉取更新
```

**分支策略**

| 分支 | 用途 | 保护规则 |
|------|------|----------|
| `main` | 主分支，稳定版本 | 需要PR审查 |
| `develop` | 开发分支 | 允许直接推送 |
| `feature/*` | 功能分支 | 开发完成后合并到develop |
| `hotfix/*` | 紧急修复 | 直接合并到main |

### 6.2 手动同步方案

**从Manus下载**

1. 登录Manus平台
2. 进入项目Code面板
3. 点击"Download all files"
4. 解压到本地项目目录

**上传到Manus**

1. 打包本地代码变更
2. 在Manus中上传更新
3. Manus验证并保存checkpoint

### 6.3 版本命名规范

| 版本类型 | 格式 | 触发条件 | 示例 |
|----------|------|----------|------|
| **主版本** | X.0.0 | 重大架构变更 | 2.0.0 |
| **次版本** | 1.X.0 | 新功能模块 | 1.4.0 |
| **补丁版本** | 1.3.X | Bug修复和小改进 | 1.3.73 |

**提交信息规范**

```
<type>(<scope>): <subject>

<body>

<footer>
```

类型（type）：
- `feat`: 新功能
- `fix`: Bug修复
- `docs`: 文档更新
- `style`: 代码格式
- `refactor`: 重构
- `test`: 测试
- `chore`: 构建/工具

## 9. 最佳实践与注意事项

### 9.1 协作最佳实践

| 实践 | 说明 |
|------|------|
| **任务粒度** | 单个任务不超过4小时工作量 |
| **文档先行** | 先完成任务规格文档，再开始编码 |
| **频繁同步** | 每完成一个小功能就同步代码 |
| **及时沟通** | 遇到问题及时反馈，不要卡住 |
| **测试驱动** | 先写测试，再实现功能 |
| **代码审查** | 重要功能必须经过ChatGPT审查 |

### 9.2 注意事项

**Manus使用注意**

- 保持todo.md与实际进度同步
- 任务规格文档要足够详细
- checkpoint要有清晰的描述
- 定期备份重要文档

**Claude Code使用注意**

- 提供足够的项目上下文
- 一次只处理一个任务
- 代码变更后及时测试
- 保持代码风格一致

**ChatGPT使用注意**

- 提供完整的代码上下文
- 明确说明审查重点
- 评估建议的可行性
- 记录有价值的建议

### 9.3 常见问题处理

| 问题 | 解决方案 |
|------|----------|
| 代码同步冲突 | 使用Git合并，保留双方有效更改 |
| 任务规格不清晰 | 与Manus沟通，补充细节 |
| 实现与规格不符 | 回顾规格文档，调整实现 |
| 测试失败 | 分析失败原因，修复代码或测试 |
| 性能问题 | 使用ChatGPT分析，针对性优化 |
