## 1. 系统概述

GRT 5.0 智能制造管理系统是面向工业清洗设备行业的一体化数字管理平台，覆盖从销售线索到终验收的全业务链条。系统采用基于角色的权限控制（RBAC），确保不同岗位用户只能访问其职责范围内的功能模块。

### 1.1 十二大核心模块

| 序号 | 模块名称 | 英文名 | 核心功能 |
|------|---------|--------|---------|
| 1 | 工作台 | Workspace | 个人看板、通知中心、智慧会议、实施路线图、工具箱 |
| 2 | 市场与销售 | Sales & Marketing | 客户管理、商机管理、联系人、线索管理、报价管理、合同管理、AI报价助手、客户门户、销售分析、客户价值视图 |
| 3 | 研发设计 | R&D Design | 需求分析、方案设计、机械设计、电气设计、BOM管理、技术文档、AI方案助手 |
| 4 | 项目管理 | Project Management | 项目列表、研发验证中心、M1启动会、M7-M9交付、项目看板、甘特图、交付管理、AI计划助手、风险管理、POS系统 |
| 5 | 生产制造 | Manufacturing | 生产看板、工序管理、工人管理、智能排程、质检管理、UWB定位、物料追踪、M8 FAT协调 |
| 6 | 客户服务 | Customer Service | 现场安装、SAT测试、终验收、售后工单、客户反馈、备件管理 |
| 7 | 人力资源 | Human Resources | HRM智能台、HR链路、培训管理、招聘管理、考勤管理、绩效管理（个人/团队/部门/BU）、薪酬管理、主管工作台 |
| 8 | 能力体系 | Capability System | 我的能力档案、能力仪表板、证据提交、能力证书、能力徽章、能力路径、红蓝对抗、团队能力分析、能力排行榜 |
| 9 | 财务管理 | Finance | 费用报销、出差申请、出差大屏、预算管理、成本管理、费用对比、超支审批、费用预测、报表定时发送 |
| 10 | AI助手 | AI Intelligence | AI助手中心、AI对话助手、AI KPI助手、数字助理、AI诊断、AI效能追踪、模型监控、知识图谱、模型训练、Agent管理 |
| 11 | 战略规划 | Strategic Planning | 资质管理、年度企业日程、全球增长追踪、变更治理 |
| 12 | 系统管理 | System Admin | 用户与权限、菜单管理、组织架构、审计日志、系统监控、安全仪表板、合规仪表板、通知渠道、Microsoft Graph配置等 |

### 1.2 项目全生命周期

- **M0-M12 研发验证阶段**: 从概念提出（M0）到终验收（M12），共13个阶段门控制点，确保项目质量层层把关。
- **T1-T15 生产工序链**: 从机加工（T1）到终验收（T15），共15道标准生产工序，覆盖设备制造全流程。

### 1.3 角色体系

系统采用分级角色体系，包括系统管理员（admin）、总监（director）、事业部总经理（bu_gm）、项目经理（bu_pm）、机械工程师（bu_mech）、电气工程师（bu_elec）、销售人员（bu_sales）、客户服务工程师（cs_engineer）、人力资源经理（hr_manager）等角色。不同角色对应不同的菜单可见性和操作权限。

## 2. RAG知识库训练操作流程

RAG（检索增强生成）知识库是GRT 5.0系统AI助手的核心数据来源。通过知识库训练，可以将企业技术文档、工艺规范、项目案例等知识导入系统，使AI助手在对话中能够自动检索并引用相关知识，提升回答的准确性和专业性。

### 2.1 访问知识库训练中心

1. 登录GRT 5.0系统
2. 在左侧导航菜单中，展开 **「AI助手」** 模块
3. 点击 **「AI助手中心」**（路径: `/ai-hub`）进入知识库管理界面
4. 权限要求: 所有登录用户均可访问（protectedProcedure）

### 2.2 上传文件

支持以下文件格式上传至知识库：

| 文件类型 | 扩展名 | 说明 |
|---------|--------|------|
| PDF文档 | .pdf | 技术规范、标准文件、操作手册 |
| Word文档 | .docx | 项目报告、设计文档、评审记录 |
| Excel表格 | .xlsx | BOM清单、参数表、统计数据 |
| 纯文本 | .txt | 会议纪要、简单技术说明 |
| Markdown | .md | 技术博客、内部wiki文档 |
| CSV数据 | .csv | 批量导入结构化数据 |
| JSON数据 | .json | API文档、配置说明 |
| 图片 | .png/.jpg/.jpeg | 通过OCR自动识别图中文字 |

**操作方式（三选一）：**
1. **拖拽上传**: 将文件直接拖拽到上传区域
2. **按钮上传**: 点击「选择文件」按钮，从本地选择文件
3. **文本粘贴**: 直接在文本框中粘贴内容，适合快速录入零散知识

### 2.3 AI智能识别

文件上传后，系统自动执行以下处理：

1. **内容解析**: 系统自动提取文件中的文字内容（图片通过OCR识别）
2. **智能分段**: 自动将长文档拆分为500-1000字的段落，确保每个知识单元完整且有针对性
3. **类别识别**: 系统自动识别每段内容属于以下六大类别之一：

| 类别代码 | 中文名称 | 说明 | 示例 |
|---------|---------|------|------|
| technical | 技术 | 技术方案、设计原理、参数计算 | 喷嘴选型指南、超声波频率选择 |
| process | 工艺 | 制造工艺、操作规程、检验流程 | 真空干燥最佳实践、FAT/SAT验收流程 |
| material | 材料 | 材料特性、兼容性、选型 | ADC12铝合金兼容性、碳钢清洗指南 |
| standard | 标准 | 行业标准、企业标准、法规 | ISO 16232清洁度标准、VDA 19标准 |
| case_study | 案例 | 历史项目经验、最佳实践 | IC-1800发动机缸体清洗线案例 |
| faq | 常见问题 | 常见问题解答、设计陷阱 | 清洗机设计常见陷阱与规避方案 |

4. **标签提取**: 自动从内容中提取关键词作为标签（如"喷嘴"、"清洁度"、"铝合金"等），便于后续检索

### 2.4 人工审核与编辑

AI识别完成后，建议进行人工审核确保知识质量：

1. **检查标题**: 确认每个段落的标题是否准确反映其内容
2. **编辑内容**: 检查内容的准确性，纠正OCR识别错误或AI分段不当之处
3. **调整类别**: 如AI分类不准确，手动修改为正确的类别
4. **管理标签**:
   - 添加遗漏的关键词标签
   - 删除不相关的标签
   - 修改不准确的标签
5. **删除无关段落**: 移除广告、版权声明、页眉页脚等无关内容
6. **手动新增段落**: 如有补充知识，可手动添加新的知识段落
7. **关联元数据**（可选）:
   - 关联项目阶段代码（stageCode，如M0、M3、M5等）
   - 关联工序代码（processCode，如T1、T3、T8等）
   - 设置知识来源（source）: 手动录入(manual)、PLM导入(plm_import)、ERP导入(erp_import)、会议纪要提取(meeting_extract)

### 2.5 确认入库（消化）

审核完成后，执行知识入库操作：

1. **选择段落**: 勾选要入库的知识段落
   - 可点击「全选」一次选择所有段落
   - 也可逐个勾选需要入库的段落
2. **点击「确认入库」按钮**: 系统将选中内容写入知识库数据库
3. **入库结果确认**: 系统返回入库成功的条数和详情
4. **AI自动检索**: 入库后，AI助手在后续对话中将自动检索相关知识
   - AI使用全文搜索 + 关键词匹配 + 相关性评分进行检索
   - 评分规则: 标题匹配+10分/次、标签匹配+5分/次、内容匹配+1分/次
   - 结果按匹配分数和使用热度综合排序

### 2.6 知识库管理

日常知识库维护操作：

1. **查看知识文档列表**:
   - 导航至AI助手中心，查看所有已入库的知识条目
   - 支持分页浏览（每页默认20条，最大100条）
2. **多维度筛选**:
   - 按类别筛选: technical/process/material/standard/case_study/faq
   - 按标签筛选: 输入关键词标签进行过滤
   - 按阶段代码筛选: M0-M12
   - 按工序代码筛选: T1-T15
   - 按关键词搜索: 搜索标题和内容
3. **查看知识使用频率**:
   - 每条知识条目有一个「相关性分数」（relevanceScore）
   - AI每次引用该条目时，分数自动+1
   - 分数越高表示该条目被引用频率越高，越有价值
4. **预填充初始知识**:
   - 系统提供一键预填充功能，自动导入约20条GRT核心技术知识
   - 涵盖: 喷嘴选型、清洁度标准（ISO 16232/VDA 19）、材料兼容性、溶剂选型、真空干燥工艺、BOM检查清单、设计陷阱、历史项目参考（IC-1800/IC-1650/IC-2000）等

### 2.7 知识检索API说明

系统提供以下知识库API端点，供前端和AI助手调用：

| 端点 | 类型 | 功能 |
|------|------|------|
| knowledgeBase.list | 查询 | 分页列表，支持category/stageCode/processCode/keyword/tags多维过滤 |
| knowledgeBase.create | 变更 | 创建知识条目 |
| knowledgeBase.search | 查询 | **RAG主端点**，全文搜索+相关性评分，返回最相关的知识条目 |
| knowledgeBase.getRelated | 查询 | 根据上下文（阶段/工序/标签）查找相关文档 |
| knowledgeBase.seed | 变更 | 预填充初始GRT技术知识数据 |
| knowledgeBase.incrementRelevance | 变更 | 文档被引用后提升相关性分数 |

## 3. 生产制造操作流程

生产制造模块是GRT 5.0系统的核心模块之一，覆盖从生产计划到工序执行、质量管控、工时采集的全流程管理。

### 3.1 生产指挥中心（生产看板）

**导航路径**: 生产制造 > 生产看板（`/production-dashboard`）

生产看板提供全局生产态势感知：

1. **T1-T15进度总览**: 统一查看所有在制项目的工序进度，包括各阶段状态（Pending/In_Progress/Completed/Alert/Blocked）
2. **设备利用率**: 实时显示各工位、设备的使用率和空闲情况
3. **质量通过率**: 汇总各工序的质检合格率统计
4. **工人分布**: 结合UWB定位数据，展示工人在各区域的实时分布
5. **质量锁定警报**: 实时显示被质量问题锁定的工序，红色高亮标注
6. **集成状态监控**: 显示UWB、ERP、PLM等外部系统的连接状态（CONNECTED/DISCONNECTED/ERROR/SYNCING）

### 3.2 智能排程

**导航路径**: 生产制造 > 智能排程（`/intelligent-scheduling`）

智能排程模块实现生产任务的自动化排程优化：

**步骤1: 创建/导入生产任务**
- 手动创建: 填写任务名称、所属事业部（buCode）、任务类型（机加工/焊接/装配/调试/测试）、预估工时、优先级（1-10级）
- 关联项目: 绑定项目ID、设置前置任务依赖关系
- 设置时间约束: 最早开始时间、最晚完成时间

**步骤2: 配置资源**
- 人员资源: 录入员工信息，标注技能等级（1-5级）、每日可用工时
- 设备资源: 登记设备名称、所属事业部、工时容量
- 工位资源: 配置工位信息、每日可用容量、每小时成本

**步骤3: 设置约束条件**
- 时间窗口约束: 限定任务的可执行时间范围
- 资源容量约束: 设定资源并行上限
- 任务依赖约束: 定义任务间的先后顺序关系
- 事业部顺序约束: 跨BU协作时的执行顺序
- 技能要求约束: 任务所需的技能和等级要求
- 换线时间约束: 设备切换不同任务的准备时间

**步骤4: 运行排程求解器**
- 选择优化级别:
  - **快速模式（fast）**: 求解时间短，适合日常快速排程
  - **均衡模式（balanced）**: 平衡求解质量和时间，推荐日常使用
  - **最优模式（optimal）**: 充分求解以获得最优结果，适合重要项目
- 设置目标权重:
  - 延迟权重（delayWeight）: 控制按时交付的优先程度
  - 换线权重（changeoverWeight）: 控制减少换线次数的优先程度
- 设定求解时间上限和排程时间范围

**步骤5: 审核排程结果**
- 查看甘特图形式的排程结果
- 验证排程合规性（系统自动校验）
- 检查资源冲突和时间重叠

**步骤6: 一键下发到工人端**
- 确认排程结果后下发至产线
- 工人在移动端查看分配给自己的今日任务
- 系统支持排程自动刷新：当工报事件发生时，自动触发排程更新

### 3.3 工序执行 (T1-T15)

**导航路径**: 生产制造 > 工序管理（`/process-management`）

#### 3.3.1 查看今日任务

1. 工人登录系统后，在工人移动端视图查看今日任务分配（`getWorkerAssignments`）
2. 系统显示: 当前分配的BOM步骤列表、所属项目/工序、预估工时

#### 3.3.2 开始执行步骤

1. 选择要执行的工步
2. 点击 **「开始」** 按钮
3. 系统自动开始计时（startTimeLog），记录开始时间和操作工人
4. 步骤状态从 `pending` 变为 `in_progress`

#### 3.3.3 完成步骤

1. 完成操作后，点击 **「完成」** 按钮
2. 系统自动停止计时（endTimeLog），记录结束时间和实际工时
3. 支持使用「一键完成并自动计时」（completeStepWithAutoTime），自动创建工时记录
4. 可添加备注说明

#### 3.3.4 物料校验

- 开始工步前，系统自动检查物料齐套率（BOM确认）
- 物料齐套率需达到95%以上方可正式开工
- 不足时系统发出预警，提示缺料明细

#### 3.3.5 AI工步建议

- 系统通过 **AI历史参照** 功能，自动查找相似历史项目（findSimilarProjects）
- 基于相似项目的工步记录，自动生成AI预设工步建议（generateAiPresetSteps）
- 支持按工序范围批量生成预设（generateAiPresetsForRange）
- 工程师可逐条审核AI预设：确认(confirmed)、修改(modified)、拒绝(rejected)
- 确认后一键采纳为正式BOM步骤（adoptAiPresetAsBomStep）
- 支持批量采纳（batchAdoptAiPresets / batchAdoptAiPresetsByProject）
- AI准确度仪表板（getAiAccuracyDashboard）持续追踪AI建议的质量

#### 3.3.6 附件管理

- 每个工步可上传附件: 工艺图纸、操作视频、检查记录等
- 支持为BOM步骤和AI预设步骤分别管理附件

### 3.4 质量管理

**导航路径**: 生产制造 > 质检管理（`/qc-management`）

质量管理模块实现质量检查与工序执行的联动管控：

#### 3.4.1 质检记录

1. 质检员登录系统，选择项目和工序
2. 执行巡检，记录检查结果
3. 对发现的缺陷进行分级:
   - **critical（严重）**: 安全隐患或功能性缺陷，必须立即处理
   - **major（较大）**: 影响产品质量但不涉及安全
   - **minor（轻微）**: 外观或非关键性问题
4. 拍照上传缺陷证据

#### 3.4.2 工序锁定机制

1. 当发现严重缺陷（critical或major）时，系统 **自动触发工序锁定**（triggerProcessLock）
2. 锁定后的影响:
   - 被锁定工序状态变为 `Blocked`
   - 下游排程任务自动变为blocked，无法继续执行
   - 系统自动创建质量预警通知（createQualityAlert）
   - 生产看板实时显示锁定警报
3. 可通过 `isProcessLocked` 接口实时查询任意工序的锁定状态
4. 通过 `getProcessLockSummary` 查看项目整体锁定概况

#### 3.4.3 质量预警通知

- 系统自动生成质量预警，推送给相关人员
- 支持按项目查看所有预警（getQualityAlerts）
- 支持筛选未读预警（unreadOnly参数）
- 一键标记预警已读（markAlertRead）或已处理（markAlertActioned）
- 批量标记所有预警已读（markAllAlertsRead）
- 实时统计未读预警数量（getUnreadAlertCount）

### 3.5 返工流程

当质检发现不合格时，执行以下返工流程：

**第1步: 触发锁定**
- 质检不合格自动触发工序锁定
- 系统记录锁定原因、严重等级、锁定人

**第2步: 提交解锁申请**
- 生产主管提交解锁请求（requestUnlock）
- 必须填写解锁原因和返工方案（unlockReason字段）

**第3步: 审批解锁**
- 经理审批解锁请求（approveUnlock）
- 可批准(approved=true)或拒绝(approved=false)
- 可添加审批意见（comments）

**第4步: 执行返工**
- 审批通过后，工序解锁
- 步骤状态变为「返工」
- 工人根据返工方案重新执行

**第5步: 重新检验**
- 返工完成后重新进行质量检查
- 通过后质检完成回调（onQualityCheckCompleted）更新状态
- 返工次数和原因由系统自动记录

### 3.6 工时管理

GRT 5.0系统具有三套独立的工时数据采集源，通过多源对账确保工时数据的真实性：

#### 3.6.1 三套工时数据源

| 数据源 | 采集方式 | 记录内容 |
|--------|---------|---------|
| UWB定位工时 | UWB标签自动定位 | 工人在各工位区域的停留时长 |
| BOM步骤打卡 | 工人手动开始/完成 | 每个BOM步骤的实际执行时间 |
| Production-Execution记录 | 系统自动记录 | 工时来源类型: MANUAL/CLOCK_IN/UWB/BADGE/AUTO_CALC |

#### 3.6.2 工时记录类型

- **REGULAR**: 正常工时
- **OVERTIME**: 加班工时
- **TRAINING**: 培训工时
- **MEETING**: 会议工时
- **OTHER**: 其他

#### 3.6.3 工时对账

1. 系统自动对比三套数据源的工时记录
2. 标记差异超过30分钟的记录，提示人工核实
3. 支持手动调整工时记录
4. 提供项目维度的工时汇总报表（getTimeSummary）

#### 3.6.4 批量导入

- 支持批量导入UWB/打卡工时数据（importTimeRecords）
- 每条记录包含: 用户、项目、阶段、日期、时间段、来源类型、设备ID、位置数据

### 3.7 UWB人员定位

**导航路径**: 生产制造 > UWB定位（`/uwb-management`）

UWB（超宽带）人员定位系统实现车间级精确定位和自动工时采集：

#### 3.7.1 绑定UWB标签

1. 进入UWB管理界面
2. 执行标签绑定操作（bindTagToEmployee）: 将UWB标签ID与工人账号绑定
3. 解除绑定: 使用 unbindTag 接口

#### 3.7.2 区域管理

1. 创建区域（createZone）: 定义车间内各功能区域
   - 区域类型: production（生产区）、assembly（装配区）、testing（测试区）、warehouse（仓库）、office（办公区）、rest（休息区）
   - 设定区域边界坐标（xMin/xMax/yMin/yMax/zMin/zMax）
   - 标记是否为工作区域（isWorkZone）
   - 设定区域容纳人数上限（capacity）
2. 查看所有区域（getAllZones）
3. 实时查看区域占用情况（getZoneOccupancy）

#### 3.7.3 实时定位追踪

1. 系统接收UWB基站上报的定位数据（reportLocation / reportBatchLocations）
   - 数据包含: 标签ID、x/y/z坐标、精度、信号强度、时间戳
2. 系统自动判定工人所在区域
3. 自动计算各区域停留时长

#### 3.7.4 工时自动采集

1. 系统根据定位数据自动计算工人在工作区域的有效工时
2. 获取员工工时汇总（getEmployeeWorkHours）: 按日期范围查询
3. 自动同步工时到排程系统（syncWorkHoursToScheduling）
4. 每日自动关闭工时记录（closeWorkHoursForDay）

#### 3.7.5 资源容量计算

- 计算单个资源的容量（calculateResourceCapacity）
- 查看所有资源的容量概况（getAllResourcesCapacity）
- 为智能排程提供实时资源可用数据

#### 3.7.6 告警管理

- 低电量标签告警: UWB标签电量低于阈值时触发告警
- 离线标签告警: 标签长时间无上报数据时触发告警
- 支持多种UWB协议: DECAWAVE、UBISENSE、SEWIO、POZYX、CUSTOM

### 3.8 阶段审批管理

生产过程中的关键节点需要审批控制：

1. **创建审批请求**: 在需要审批的节点（阶段开始/阶段完成/阶段通过/异常处理）创建审批请求
2. **待审批列表**: 审批人登录后查看分配给自己的待审批项（getPendingApprovals）
3. **审批操作**: 批准(APPROVED)或拒绝(REJECTED)，附上审批意见
4. **通知推送**: 审批请求和结果自动推送通知
   - 支持多渠道: 企业微信(WECOM)、钉钉(DINGTALK)、邮件(EMAIL)、短信(SMS)、系统内通知(SYSTEM)
5. **审批状态**: PENDING(待审)、APPROVED(已批)、REJECTED(已拒)、CANCELLED(已撤)、AUTO_APPROVED(自动审批)

## 5. 研发验证操作流程

**导航路径**: 项目管理 > 研发验证中心（`/rd-verification`）

### 5.1 研发验证中心

研发验证中心是M0-M12阶段门管控的统一管理界面，包含四个核心功能标签页：

1. **阶段概览（StageOverview）**: M0-M12项目阶段进度总览，显示各阶段状态和完成率
2. **门禁管理（GateManagement）**: 配置各阶段的检查项（手动检查 + 自动验证源），定义通过条件
3. **评审管理（ReviewManagement）**: 管理阶段评审流程，记录评审结论
4. **拉动信号（PullSignals）**: 管理跨阶段的拉动触发信号

**关键统计数据**:
- 在验项目总数
- 平均通过率
- 拉动信号总数
- 必检项数量

### 5.2 M3阶段门检查示例

以M3（详细设计）阶段为例，说明阶段门检查流程：

#### 五维度检查

| 维度 | 检查内容 | 验证方式 |
|------|---------|---------|
| 商业价值 | 项目商业可行性确认 | 人工评审 |
| 范围 | 项目范围定义完整性 | 自动检查: 范围文档是否存在 |
| 资源 | 资源配置充分性 | 自动检查: 预算审批状态、PM指派状态 |
| RACI矩阵 | 责任分配矩阵完整性 | 自动检查: RACI定义是否完整 |
| 风险 | 风险评估完整性 | 自动检查: 风险评估记录是否存在 |

#### 自动验证项

系统自动验证以下检查项，无需人工操作：
- 项目预算是否已审批通过
- 项目经理（PM）是否已指派
- 风险评估是否已完成
- RACI矩阵是否已定义
- 范围文档是否已上传

#### 检查清单

M3阶段包含约15项检查清单:
- **11项必检项（mandatory）**: 必须全部通过才能进入下一阶段
- **4项推荐项（recommended）**: 建议完成但非强制要求

### 5.3 设计变更管理

**导航路径**: 战略规划 > 变更治理（`/change-management`）

设计变更管理流程：

**第1步: 创建变更事件**
- 提交变更申请: 描述变更原因、影响范围、紧急程度

**第2步: 影响分析**
- 评估变更对BOM的影响
- 评估变更对采购订单的影响
- 评估变更对生产进度的影响
- 评估变更对成本的影响

**第3步: 审批**
- 按变更等级执行不同的审批流程
- 重大变更需要多级审批

**第4步: 执行**
- 审批通过后执行变更
- 自动关联BOM更新
- 自动关联采购订单调整
- 通知所有相关人员

### 5.4 M0-M12全阶段流程

项目从M0到M12依次通过以下阶段门：

1. **M0 概念提出** → M1: 需客户需求签字确认、技术方案可行性确认
2. **M1 需求分析** → M2: 需求规格书完成
3. **M2 概念设计** → M3: 概念方案评审通过
4. **M3 详细设计** → M4: BOM冻结、所有评审问题关闭
5. **M4 设计验证** → M5: 验证报告完成
6. **M5 设计评审** → M6: 评审记录签字确认
7. **M6 试制** → M7: 试制总结通过
8. **M7 生产准备** → M8: 生产计划确认
9. **M8 FAT测试** → M9: FAT报告客户签字
10. **M9 出厂验收** → M10: 出厂报告完成
11. **M10 现场安装** → M11: 安装记录确认
12. **M11 SAT测试** → M12: SAT报告客户签字
13. **M12 终验收**: 验收证书签发，项目完成
