## 1. 概述

本文档描述GRT智能系统的权限管理架构设计，包括角色定义、模块权限、群组权限、敏感数据访问控制等核心内容。该架构基于简道云用户清单和GRT组织架构设计，旨在实现精细化的权限控制，保护敏感数据安全，同时支持灵活的群组管理功能。

### 1.1 设计目标

权限架构设计遵循以下核心目标：

| 目标 | 描述 |
|------|------|
| **最小权限原则** | 用户仅获得完成工作所需的最小权限 |
| **职责分离** | 敏感操作需要多角色协作，避免单点风险 |
| **数据保护** | 薪资、身份证等敏感数据严格控制访问 |
| **审计追踪** | 敏感数据访问全程记录，支持事后审计 |
| **灵活扩展** | 支持群组权限，便于部门通用设定 |

### 1.2 架构层次

```
┌─────────────────────────────────────────────────────────────┐
│                      系统管理员 (Admin)                      │
├─────────────────────────────────────────────────────────────┤
│                        总监 (Director)                       │
├─────────────────────────────────────────────────────────────┤
│     HR经理      │    财务经理     │     部门经理            │
├─────────────────────────────────────────────────────────────┤
│     HR专员      │    财务专员     │     组长/主管           │
├─────────────────────────────────────────────────────────────┤
│                      普通员工 (Employee)                     │
├─────────────────────────────────────────────────────────────┤
│                        访客 (Guest)                          │
└─────────────────────────────────────────────────────────────┘
```

## 5. 敏感数据访问控制

### 5.1 敏感数据分类

| 敏感级别 | 数据类型 | 访问要求 |
|----------|----------|----------|
| 极高 | 身份证号、银行卡号、个人薪资 | 仅HR/财务可访问，需记录日志 |
| 高 | 薪酬结构、项目成本、合同信息 | 需相关权限，建议记录日志 |
| 中 | 联系方式、绩效评估、面试评价 | 需相关权限 |
| 低 | 基本信息、培训记录、任务信息 | 一般员工可查看 |

### 5.2 敏感数据访问规则

| 数据类型 | 访问条件 | 是否审计 |
|----------|----------|----------|
| 个人薪资 | 仅本人、HR、财务、直接主管可查看 | ✅ |
| 身份证号 | 仅HR、财务可查看 | ✅ |
| 面试评估 | 仅HR、面试官、部门经理可查看 | ✅ |
| 项目成本 | 仅项目经理、财务、总监可查看 | ✅ |
| 合同信息 | 仅销售、财务、法务、总监可查看 | ✅ |

### 5.3 审计日志要求

敏感数据访问需记录以下信息：

- **访问者**: 用户ID、姓名、角色、部门
- **访问时间**: 精确到秒
- **访问模块**: 模块ID和名称
- **访问数据**: 数据类型和关键标识
- **访问方式**: 查看/导出/编辑/删除
- **访问来源**: IP地址、设备信息
