# TPL-经验教训库

> **适用范围**：全公司项目经验教训收集与预防
> **更新频率**：项目结项后 2 周内提交，持续更新
> **审批流程**：项目经理提交 → 部门主管评审 → 知识管理员发布

## 模板

### 经验教训条目

| 字段 | 说明 |
|------|------|
| 编号 | LL-YYYY-NNN（Lessons Learned） |
| 来源项目 | 项目名称和编号 |
| 所属 BU | |
| 项目阶段 | M0-M12 的哪个阶段 |
| 类别 | 技术 / 管理 / 供应商 / 质量 / 沟通 / 安全 |
| 事件描述 | 发生了什么 |
| 根本原因 | 为什么发生（5Why 分析） |

| 教训总结 | 从中学到了什么 |
| 预防措施 | 如何避免再次发生 |
| 已固化到 | 是否已纳入 SOP/Checklist/模板 |
| 提交人 | |
| 提交日期 | |
| 严重等级 | 高/中/低 |

#### LL-2025-001：长周期物料未提前采购导致项目延期 3 周

| 字段 | 内容 |
|------|------|
| 编号 | LL-2025-001 |
| 来源项目 | 海外XX汽车焊装线项目（PRJ-2025-018） |
| 所属 BU | 海外 |
| 项目阶段 | M6（采购阶段） |
| 类别 | 管理 |
| 事件描述 | 项目中 3 台伺服驱动器（交期 12 周）在 M6 才下单，导致设备到货晚于装配计划 3 周，整体项目延期 3 周 |
| 根本原因 | 1. M5 设计评审时未识别长周期物料；2. 采购清单未按交期排序；3. 没有长周期物料预警机制 |

| 提交日期 | 2025-10-15 |

## 使用说明

1. **提交时机**：项目结项复盘时必须提交，项目执行中发现重要教训也应及时提交
2. **固化闭环**：每条教训必须转化为可执行的预防措施，并注明是否已纳入 SOP/Checklist
3. **AI 检索**：Copilot 在新项目启动时自动检索类似项目的历史教训，提供风险提示
4. **新项目对照**：项目经理在 M0 阶段需查阅同类项目的经验教训，纳入风险清单
5. **统计分析**：每季度统计教训分布（按类别/BU/阶段），识别系统性问题
6. **保密处理**：涉及客户信息的教训需脱敏处理后再发布
